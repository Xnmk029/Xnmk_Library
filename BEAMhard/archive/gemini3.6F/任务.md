## [STRICT CONSTRAINTS & CRITICAL DIRECTIVES]

1. **GDScript 语法绝对纯净性：** 必须严格使用 Godot 4.x 的 GDScript 规范（例如 `@export`, `@onready`, Typed GDScript）。**严禁混入任何 C# 语法**（如 `using Godot;`、`public class`、C# 类型的显式声明习惯或大小写风格混淆）。

3. **MCP 调用严谨性：** 所有针对 Godot 编辑器的操作均需构建标准的 MCP Tool Calls JSON 载荷，指令必须具备原子性与错误回滚机制。

## [WORKFLOW & PHASE PROTOCOLS]

### 阶段 1：Mod 解析、刚性化转译与软体轮胎解耦 (Asset Parsing & Physics Conversion)

- **任务 1.1（JBeam 解析）：** 解包并提取 BeamNG Mod 文件（包含 `.jbeam` 结构定义、`.dae`/`.obj` 网格模型以及材质贴图）。

- **任务 1.2（刚体与软体转换）：**

  - **车身框架：** 将原 JBeam 中定义车身梁框架的软体节点网络，转译为 Godot 4 的刚体结构（`RigidBody3D` + `CollisionShape3D` 组合，或组合式 Skeleton 节点）。

  - **轮胎独立提取：** 提取原 JBeam 轮胎组节点，将其构建为 Godot 的独立 `SoftBody3D` 悬挂/轮毂交互组件。显式配置高摩擦系数物理材质（`PhysicsMaterial`：`friction >= 1.2`, `rough = true`）。

- **任务 1.3（绑定与对齐）：** 将 3D 网格模型绑定至转换后的节点树，确保所有挂载点（Mounting Points）、转向枢轴点（Pivot Points）无错位。

### 阶段 2：引擎声学仿真与音频流管线 (Acoustic Simulation & Synthesis)

- **任务 2.1（音频提取）：** 提取 Mod 包内的原生 `.wav` 引擎与环境音效。

- **任务 2.2（Engine Sim 接口集成）：** 调用开源项目 `engine-sim` 的参数配置文件逻辑，根据 Mod 内的引擎参数（汽缸数、排气歧管长度、点火顺序、变速箱齿比）合成实时声学响应曲线。

- **任务 2.3（Godot 音频总线挂载）：** 在 Godot 中构建基于 RPM、Throttle、Load 多维驱动的 `AudioStreamPlayer3D` 混合节点网络。

### 阶段 3：自动化试车场搭建与物理感知验证 (Proving Ground & Spatial Validation)

- **任务 3.1（环境与天空盒）：** 通过 MCP 搜寻/配置高动态范围 HDRI 天空盒，构建 `WorldEnvironment` 节点（启用 ToneMap 与 SSR）。

- **任务 3.2（测试跑道生成）：** 程序化生成标准车辆试车场（Vehicle Proving Ground），必须包含：

  1. **悬挂测试区：** 波浪路（Belgian Cobblestone）、连续搓板路（Asymmetric Bumps）。

  2. **转向测试区：** 标准蛇形绕桩（Slalom Track）与高侧倾弯道。

  3. **涉水测试区：** 具水体阻力（Fluid Drag）与浮力模拟的深水池。

- **任务 3.3（车辆测试脚本）：** 编写控制脚本驱动车辆完成上述全套测试，实时回传悬挂行程与阻尼数据。

### 阶段 4：NPR 动漫风格化渲染与 UI 搭建 (Stylized Rendering & FR-Legends Style UI)

- **任务 4.1（Anime Toon Shader）：** 为车辆及场景编写 Godot 自定义 `shader_type spatial` 渲染器：

  - 基于阶梯式光照函数（Cel-Shading Light Ramp）的漫反射渲染。

  - 基于法线外扩（Inverted Hull）或深度/法线后处理（Post-Process Edge Detection）的描边卡线效果。

- **任务 4.2（FR 传奇风格 UI）：** 构建高对比度、倾斜几何板块的 Anime 风格 UI（使用 Control / CanvasLayer 节点）：

  - 动态 RPM 仪表盘、斜角速度数字显示、踏板输入实时状态条。

### 阶段 5：程序化城市网格与 3D 矢量瓦片无极地图系统 (Procedural City & 3D Vector Tile Map)

* **任务 5.1（程序化城市地图生成）：**
  - **路网算法：** 使用 L-System 或 基于 Voronoi / 网格图（Grid Graph）的算法，程序化生成包含主干道、次干道与街区的城市地图拓扑。
  - **体块拉伸与 Prop 摆放：** 根据街区多边形（Block Polygons）自动拉伸生成不同高度的建筑 Base Mesh，并自动布设路灯、红绿灯与道路标线。

* **任务 5.2（3D 矢量瓦片管线 - Vector Tile Pipeline）：**
  - **数据切片与 QuadTree 索引：** 将生成的城市地图矢量数据（道路线、建筑轮廓、POI 节点）切分为标准的四叉树瓦片层级结构（Tile Coordinates: $z/x/y$）。
  - **矢量网格化 (Vector-to-Mesh)：** 编写 GDScript 工具，在运行时将矢量几何（LineString/Polygon）实时转换为 Godot 的 `ArrayMesh`。
  - **屏幕空间线宽补偿 Shader：** 编写自定义 3D 矢量 Shader，确保道路与边界描边在不同的相机距离/缩放比例下，保持恒定的屏幕像素宽度或光滑抗锯齿边缘。

* **任务 5.3（无极缩放交互与 LOD 动态加载）：**
  - **无极缩放相机 (Seamless Zoom Camera)：** 构建支持平滑平移（Pan）、旋转（Pitch/Yaw）与无极缩放（Zoom）的 `Camera3D` 控制器。缩放时实现正交视角（Orthographic）与透视视角（Perspective）的平滑过渡。
  - **瓦片动态加载/卸载 (Tile Streaming)：** 基于相机视锥体（Frustum Culling）和当前 Zoom 级别，动态实例化/销毁 3D 矢量瓦片 Chunk。
  - **UI/HUD 映射与 POI 悬浮：** 实现类似车载导航/大地图系统的 HUD 界面，地名与 POI 标签随着 Zoom 级数进行 LOD 隐现与平滑缩放，不产生视觉挤压。
