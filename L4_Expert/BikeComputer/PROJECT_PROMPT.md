# 任务背景

你是一名全栈嵌入式产品工程师。请基于下方给定的**固定硬件 BOM**，从零规划并设计一款功能完整、UI 精美的商用级**自行车码表（GPS Cycling Computer）**，完成从「产品定义 → 硬件系统设计 → 固件架构 → 结构外观建模」的完整产品设计闭环。评测以**最终产品完成度**为核心指标：方案是否真正吃透了每颗器件、论证是否有量化依据、结构是否可装配可打印、UI 是否达到消费级水准。

## 1. 产品定义与功能规划（`docs/product_spec.md`）

- 给出完整功能清单与功能树：骑行数据显示（速度/距离/时间/海拔/爬升/卡路里/航向等）、离线地图、轨迹记录与回放、计步、罗盘、时钟表盘、系统设置、电源管理等，逐项说明实现路径。
- UI 页面树与交互流：所有页面清单、页面切换关系、编码器（旋转/短按/长按）驱动的完整操作模型、状态栏定义。
- **可行性量化论证**：每条核心功能给出资源占用估算与推导过程，至少覆盖——
  - 显示带宽：240×240 RGB565 全帧缓冲大小、60fps 所需 SPI 速率、LVGL 类 GUI 的部分刷新策略与可达帧率论证；
  - 内存预算：帧缓冲、地图瓦片缓存、轨迹缓冲、UI 资源在 512KB RAM 内的分配表；
  - 存储带宽与容量：瓦片/轨迹/配置的读写速率与容量估算；
  - 续航：分器件电流预算表 → 典型工作电流 → 700mAh 下的续航小时数推导；
  - GPS：NMEA 数据流、波特率/更新率配置、冷/热启动时间预期。
- 明确标注哪些功能"可做 / 受限做 / 不可做"，并给出理由。

## 2. 硬件系统设计（`docs/hardware_design.md`）

- 系统框图（ASCII 图即可）与电源树（电池 → MCP73831 充电 → LP5907 → 3V3 各用电域）。
- **完整引脚分配表**：AT32F435CGU7 的 QFN48 引脚编号、外设复用（SPIx/I2Cx/UARTx/TIMx/ADC/GPIO）、上下拉与备注；须无冲突且引脚总数不超封装可用 GPIO 数。
- 器件选型补充说明：BOM 之外必要的无源件（如充电指示、按键、USB 连接器、法拉电容/RTC 电池等）。
- 结构与电气注意事项：GPS 天线净空与摆放、屏幕排线、SD 卡槽与 USB 口位置、ESD/防水考量。

## 3. 固件架构（`docs/firmware_arch.md` + `firmware/`）

- 分层架构图：HAL/BSP → 驱动 → 服务 → 应用/UI；给出 `firmware/` 完整目录树。
- 数据流设计：传感器/GPS → 数据处理 → UI 的解耦方案（建议发布-订阅/数据中心模式），页面生命周期管理方案。
- 存储方案：FAT32 文件组织、轨迹文件格式（标准 GPX）、离线地图瓦片存储格式（自定义二进制瓦片设计：来源→转换工具→目录结构→运行时加载）、配置掉电保存机制。
- 关键算法说明：经纬度 ↔ 瓦片坐标换算、轨迹抽稀、速度/距离滤波、罗盘校准。
- `firmware/` 源码要求：目录分层完整，关键文件为**真实可读的实现代码**而非占位符，至少包含——ST7789 初始化与 SPI/DMA flush、编码器读取（TIM 编码器模式）、GPS NMEA 解析、LVGL 移植层（display flush / input read）、页面管理器与一个数据页示例、GPX 轨迹写入、SD/FATFS 挂载、电源管理（电量 ADC / 充电状态 / 休眠）。

## 4. 可运行 UI 演示（`ui_demo/`）

- 在 PC 上可运行的 240×240 像素级 UI 演示，技术栈自选（单文件 HTML Canvas、Python 等均可），**必须离线可运行、不依赖 CDN/网络资源**。
- 至少实现 4 个核心页面（如：时钟表盘、骑行数据、地图轨迹、菜单/设置），页面间可用键盘模拟编码器旋转/按压完成切换。
- 视觉水准按消费级码表要求：排版、配色、圆角组件、过场动画意图，需有真实内容绘制而非色块占位。

## 5. FreeCAD 结构建模（`cad/`）

- `cad/build_model.py`：FreeCAD Python 参数化脚本，**必须可通过 `freecadcmd build_model.py` 无头执行且无报错**；关键尺寸（整机长宽高、壁厚、开孔位置等）集中定义为参数。
- 生成 `cad/out/BikeComputer.FCStd`，并导出 STEP 与 STL。
- 装配体零件清单（每个零件为独立命名实体）：上壳（含 1.54" 屏视窗与镜片台阶）、下壳（含码表座接口）、PCB 总成（主板 + 屏幕模组 + 电池 + GPS 天线 + 编码器的堆叠占位）、编码器旋钮、USB-C 充电口开孔、SD 卡槽开孔、固定结构（螺丝柱或卡扣）。
- 工程约束：整机外形 ≤ 60×60×20mm；外壳壁厚 ≥1.2mm（光固化可打印）；主要外露面圆角 ≥1mm；开孔与各器件位置须与 `hardware_design.md` 的布局设计一致。
- `render/`：≥3 个视角的产品预览图（可导出 STL 后用任意离线方式渲染，或直接说明 FCStd 的查看方式）。

# 交付与限制要求

- **评测环境禁止联网**：所有方案基于给定 BOM 与通用工程知识完成；交付物不得引用网络资源，所有工具链假设离线可用。
- 所有文档使用中文撰写；引脚表、功耗表、内存预算表等必须以表格给出具体数值与推导过程，不接受"性能足够"式定性结论。
- `freecadcmd cad/build_model.py` 退出码必须为 0；生成的 FCStd 打开后无 recompute 错误。
- `ui_demo/` 附一行启动命令或双击入口，3 秒内可看到第一屏。
- 全部交付物不得包含 TODO / FIXME / 空函数体等未完成占位符；代码注释清晰。
- 允许模型基于自身知识借鉴业界已知设计模式；若识别出该 BOM 对应的公开开源设计，可借鉴但须自行完成全部交付物。
