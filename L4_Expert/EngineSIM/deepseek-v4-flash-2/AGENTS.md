来说明冲突，不得擅自变通。

## 1. 绝对工作区限制

- 所有读写操作（代码、文档、资源、临时文件、下载落盘）仅限本工作区及系统
  明确授权的可视化输出 / 临时目录。
- 禁止访问、读取、修改、复制或删除工作区以外的本地文件（包括但不限于
  `G:\产品\新benchmark\EngineSIM\claude-opus-5\...`、`G:\产品\新benchmark\EngineSIM\deepseek-v4-flash\...`、
  `G:\产品\新benchmark\EngineSIM\deepseek-v4-flash-1\...`、`C:\Users\Administrator\...`）。
- 确需引用工作区外资料（构建期依赖、用户主动提供的参考文件）时，必须先向
  用户说明并获得明确同意；只读使用；禁止写入；最终回复必须披露引用了什么、
  用于何处。

## 2. 禁止越狱

禁止任何绕过沙箱、权限审批或文件系统限制的行为，包括但不限于：

- 隐藏或伪装命令意图、拆分命令规避审批；
- 伪造环境变量 / 路径 / 文件类型；
- 利用 junction / 符号链接 / 硬链接访问受限目录或读写工作区外文件；
- 以“仅测试”“只读”名义执行实际写操作；
- 覆盖、修改或删除权限配置、审批规则、审计记录；
- 在被拒绝后换一种方式重试同一越权操作。

需要更高权限时必须走正规审批流程，等待用户批准。

## 3. 需求二次反问验证

对用户提出的任何新需求，执行前先用自己的话复述范围与目标（改什么、为什么、
影响面、验收标准）。出现以下任一情形必须停下来反问确认，不得直接执行：

a) 涉及删除 / 覆盖 / 移动文件或目录；
b) 涉及工作区以外文件的访问；
c) 涉及网络下载、外部 API 或第三方服务调用；
d) 需求表述模糊、存在多种合理解释或明显超出既有任务范围；
e) 可能影响工作区以外的进程、项目或用户其他数据。

得到用户明确确认后再动手；确认前不得“先做一部分”。

## 4. 变更自检

每轮改动完成后自查：是否存在越界读写、越狱尝试或未披露的外部引用；如有，
必须撤回并如实报告。
