# 原题与难度分析

分析对象是用户指定的 `F:/bench-runs/mimo-v2.6-flash/20260921-231035-BilibiliUserscript/PROMPT.md`，与项目 `PROJECT_PROMPT.md` 的字节及 SHA-256 完全一致。

## 原题要求和歧义

| 能力 | 明确要求 | 缺少的信息 |
|---|---|---|
| 交付 | 原生单文件 Userscript、最小权限 | 脚本管理器和上下文 |
| 数据获取 | 已返回的公开属地，不猜位置 | 展示对象、具体字段、数据来源优先级 |
| 动态适配 | SPA、异步、幂等 | 路由、组件类型、Shadow DOM、复用范围 |
| 布局 | 贴合页面、不遮挡 | 插入位置、可量化断言 |
| 降级 | 安静且可识别的状态 | 未获取和未返回的区分 |
| 网络 | 元数据声明请求 | 主动查询是否允许、普通 fetch 的声明方式 |

“在电脑端页面显示归属地”没有明确要求逐条评论展示。现有 `mimo-v2.6-flash` 输出是“本机出口 + 本页属地汇总”面板，并查询 `x/web-interface/zone`。它与 BiliReveal 的逐条评论路线不同，单凭旧题不能把这一路线直接判成作弊或完全偏题；其自测能验证面板，但不能验证评论归属对应。

“公开接口已经返回”也可能被理解为“请求公开接口取得结果”，因此不能把后来制定的零主动请求要求倒用到历史榜单。`@connect` 主要约束 GM 跨域能力，并不替代普通页面 fetch 的 CORS。代码包含某个声明不是行为已经安全的证明。

## 难度

| 范围 | 判断 |
|---|---|
| 给定字段、冻结 DOM、单一种评论 | L1 |
| 给定三代组件契约，处理楼中楼、复用、SPA、大整数 ID | L1 上沿至 L2 下沿 |
| 无资料，在真实 B 站反推 Vue2/Vue3/Lit 与多层 Shadow DOM | L2 集成任务 |
| APP 接口、签名、账号主页、闭合 Shadow Root、持续站点维护 | 超出原题，应另立项目或扩展版本 |

目录保留 `L1_Basic` 和历史分类，`benchmark.json` 写明实际难度。v2 通过公开契约减少站点漂移、训练记忆和调研时间的噪声，重点测实现正确性。真实站点探索作为另一项证据记录。

## 参考金标

BiliReveal 有长期公开维护、三代组件适配和实际数据路径，适合作为结构参照。版本固定为 v2.3.0，而不是随时拉 latest。

原版与原题仍有不一致：缺失字段往往不展示状态；按初始路由启用策略；专栏作者定位会主动请求；部分路径拼接 HTML。因此原版不预设满分。保存原始 Lite/标准版及许可证，另通过公开补丁生成题面一致的修订金标。二者都接受同一个独立判分器。

## 新题面与可比性

v2 明确每条评论、`reply_control.location`、字符串 ID、三代组件和跨类型 SPA；明确零主动请求/零持久化、纯文本、原生标签保留、复用清空、窄窗口与控件要求，并给出数据结构。

这是新题面，旧输入原文继续保留。历史输出的 v2 回放结果仅为 `diagnostic-v1`，不能解释为旧题正式分，更不能与使用新题重新生成的模型直接混排。

模型只接收题面和公开契约，金标/评分器/反例参数保留在独立评测工作区。源码行数、注释承诺、自带测试 PASS、API Hook 数量都不直接换成得分。一次没有出站请求也不证明所有沉睡分支永远不会出站。
