Injection Strategies

Relevant source files
  • CHANGELOG.md

This page documents the three distinct injection strategies used by the IP Location Display System to insert IP attribution text into various Bilibili page types. The strategies are automatically selected based on the URL pattern using a router-based approach. For information about how the userscript is injected into pages, see Script Injection Architecture.

Overview

The IP Location Display System employs three different technical approaches to inject location information into comments, each tailored to specific Bilibili page architectures:

StrategyTechniqueTarget PagesComplexity
Lit Custom ElementsProxy-based component interceptionVideo pages, new list pages, opus pages, coursesHigh
bbComment PatchingPrototype method interceptionFestival pages, blackroom ban pages, old bangumi pagesMedium
MutationObserverDirect DOM manipulationActivity pages, manga pages, articles, topic pagesLow

The system uses a Router class to match URL patterns and dispatch to the appropriate strategy.

Strategy 1: Lit Custom Elements Interception

This strategy targets Bilibili's modern pages that use Lit-based Web Components for comment rendering.

Architecture

Implementation Details

The createPatch function wraps the component's update method with location injection logic:

public/bilibili-web-show-ip-location.user.js90-116

Location Injection Process

  1. Shadow DOM Access: Queries the shadow root for #pubdate element
  2. Location Retrieval: Calls getLocationString(thisArg.data) to extract location from component data
  3. Element Creation: Creates or updates a #location div element
  4. DOM Insertion: Inserts the location element after the pubdate element using insertAdjacentElement("afterend", locationEl)

Target Pages

This strategy is used for:

  • https://www.bilibili.com/video/*
  • https://www.bilibili.com/list/*
  • https://www.bilibili.com/opus/*
  • https://www.bilibili.com/cheese/play/*

HTML String Manipulation

This strategy modifies HTML strings before they're inserted into the DOM. Two regex patterns are used:

ContextRegex PatternReplacement
Normal Comments/<span class="reply-time">(.*?)<\/span>/<span class="reply-time">$1</span><span class="reply-location">${location}</span>
Blackroom/<span class="time">(.*?)<\/span>/<span class="time">$1&nbsp;&nbsp;${location}</span>

Target Pages

This strategy is used for:

  • https://www.bilibili.com/festival/* (festivals/events)
  • https://www.bilibili.com/blackroom/ban/* (blackroom ban pages)
  • Old-style bangumi pages (detected dynamically)
  • Old-style dynamic pages (detected dynamically)

This strategy uses DOM observation to detect comment elements and directly manipulates them to insert location information.

Vue Instance Data Access

This strategy accesses location data from Vue component instances attached to DOM elements:

public/bilibili-web-show-ip-location.user.js157-168

The data path depends on the comment type:

  • Main replies: element.__vue__.vnode.props.reply.reply_control.location
  • Sub-replies: element.__vue__.vnode.props.subReply.reply_control.location

Target Pages

This strategy is used for:

  • https://www.bilibili.com/blackboard/* (activity pages)
  • https://manga.bilibili.com/detail/* (manga detail pages)
  • https://www.bilibili.com/read/* (article pages)
  • Dynamic comment sections on space pages
  • Topic detail pages
