# 任务背景

仓库中已有一个「B 站电脑端 IP 属地」油猴脚本（Userscript）：它只展示页面或公开接口**已经返回**的归属地信息，不推断精确位置，也不自行发起网络请求。现在需要为这类脚本建立一套**可重复、离线、机器可判定**的自动验收——给定任意一个声称符合该行为契约的 `.user.js`，验收器应能在不联网、不安装第三方包的前提下判断它是否达标，并给出结构化报告。

本项目的核心目标是：理解 Userscript 元数据与运行时行为契约、用轻量 DOM 桩模拟单页应用（SPA）的动态路由与异步加载、把「不能重复插入、不能拦截原控件、不能偷偷联网」这类行为约束变成可执行断言。

# 需求范围

忽略工作区内其他文件，只交付一个**零外部依赖**的 Node.js 验收项目。被测脚本路径由命令行参数给出，验收器不得修改被测脚本。

## 验收对象的行为契约（据此设计检查项）

被测 `.user.js` 应满足：

- 元数据块 `// ==UserScript== ... // ==/UserScript==` 完整，含 `@name`、`@namespace`、`@match`、`@run-at`、`@grant`。
- 适用范围覆盖 `bilibili.com` 电脑端；对移动端与账号/通行证类子域（`m.`、`passport.`、`account.`、`message.`）不生效。
- 权限最小化：没有真实跨域需求时不得申请 `GM_xmlhttpRequest` 一类广域权限。
- 只读取页面已经存在的数据；**自身不发起任何网络请求**（不 fetch、不 XMLHttpRequest、不加载远程资源）。
- 不收集、不上传、不持久化用户隐私数据。
- 支持 SPA：路由切换或异步插入新内容后，新增条目同样被标注。
- 同一目标节点**最多标注一次**，多次 DOM 更新不重复插入。
- 字段缺失或数据异常时静默降级，给出可识别但不打扰的占位，不抛异常。
- 注入节点贴合原布局，不遮挡原控件与弹层，不改变原控件布局。
- 代码中不得有 TODO 或未完成占位符。

## 功能要求

验收器须实现下列检查项，每项独立报告 `PASS`/`FAIL` 与依据。

### A. 静态检查（读被测脚本源码）

- `A1` 元数据块存在且字段齐全（至少 `@name`、`@namespace`、`@match`、`@run-at`、`@grant`）。
- `A2` 域名范围正确：覆盖电脑端 `bilibili.com`；`m.`、`passport.`、`account.`、`message.` 子域不在生效范围内。
- `A3` 权限最小化：无 `@grant GM_xmlhttpRequest` 等广域权限；若脚本确有跨域需求，须有可判定的正当性证据，否则判 FAIL。
- `A4` 红线扫描：不含 `TODO`/`FIXME`/未实现占位；不通过远程地址加载第三方脚本或样式。
- `A5` 隐私红线：不出现向非 `bilibili.com` 域外发数据的调用；不写入本地持久化存储。

### B. 运行时行为检查（在无头 DOM 中加载被测脚本）

- `B1` 初始渲染：页面已有归属地数据时，目标条目被标注且内容正确。
- `B2` SPA 路由切换：模拟路由变化后重新渲染，功能仍生效。
- `B3` 异步加载：模拟评论分页/懒加载后插入的新条目，同样被标注。
- `B4` 幂等：对同一目标节点连续触发多次 DOM 更新，标注节点数量不超过 1。
- `B5` 降级：缺失归属地字段时，不抛异常且给出可识别占位。
- `B6` 不打扰：注入节点不遮挡、不改变原控件布局（用可判定的样式或 DOM 断言，例如不采用覆盖式定位、不拦截指针事件）。
- `B7` 零网络：在 DOM 桩中拦截 `fetch`、`XMLHttpRequest`、`Image`，断言被测脚本运行期间未发起任何请求。
- `B8` 异常隔离：任一用例抛错不影响其余用例，错误被记录为该项 FAIL。

### C. 自检（验收器自身的可验证性）

- 提供 `--self-test`：用内置的**正例 fixture**与**反例 fixture**跑完整流程，断言正例得到 `PASS`、反例得到 `FAIL`，且反例至少触发 `A3`、`A4`、`B4` 中的两项。
- 反例 fixture 必须是刻意违反契约的最小脚本，用来证明验收器不是「永远 PASS」。

## 报告与退出码

- 支持 `node accept.js --script <被测脚本路径>`；无参数时默认在工作目录内查找 `bilibili-ip-location.user.js`。
- 支持 `--json` 把机器可读结果打印到标准输出，结构固定：

```json
{
  "script": "<被测脚本路径>",
  "verdict": "PASS | FAIL",
  "summary": { "pass": 0, "fail": 0 },
  "checks": [ { "id": "A1", "status": "PASS", "detail": "..." } ]
}
```

- 退出码：全部通过为 `0`，任一 `FAIL` 为 `1`，用法错误为 `2`。
- 默认同时输出人类可读摘要。

# 交付形态

在工作目录**根层**交付以下文件（不建子目录、不建点文件、不生成 `node_modules`）：

- `accept.js` —— 验收器入口（可按需拆成 2–4 个 `.js` 模块，均放根层）。
- `fixture-ok.user.js` —— 符合契约的正例假脚本。
- `fixture-bad.user.js` —— 至少违反两项契约的反例假脚本。
- `README.md` —— 用法、检查项清单、报告字段说明、自检命令。
- 可选：示例报告 `accept.example.json`。

# 交付与限制要求

- 只用 Node.js 原生能力（`node:fs`、`node:vm`、`node:assert` 等），**不依赖任何第三方包**，运行时**不联网**。
- 允许自实现轻量 DOM 桩（元素、属性、事件、`querySelector` 等最小集合），只要足以驱动被测脚本的注入逻辑。
- 验收器不得修改、不得重写被测脚本；读取失败要给出明确错误与退出码。
- 代码须可直接运行，不得包含 `TODO` 或未完成占位符。
- 交付文件之间不得出现跨目录引用。
