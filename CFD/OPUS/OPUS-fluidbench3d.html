Physics model — declared

Position Based Fluids (PBF) — Macklin & Müller, SIGGRAPH 2013 — a Position Based Dynamics constraint solver enforcing a density constraint C_i = ρ_i/ρ₀ − 1 = 0. This is a real-time approximation, not a Navier–Stokes reference solver: it is incompressible only to solver tolerance, viscosity is artificial (XSPH), and no vorticity confinement is applied.
  • Density kernel Poly6, gradient kernel Spiky, support radius h = 2.2·d.
  • λi = −Ci / (Σ|∇Ci|² + ε), with ε auto-derived from the initial lattice (scale-invariant CFM relaxation).
  • Tensile instability correction s_corr = −k (W(r)/W(0.2h))⁴, k = 1e−4.
  • Jacobi position update, Δt = 1/60 s. Iterations and substeps are set per tier. PBF propagates pressure about one particle layer per iteration, and the standard column is ~14 layers deep at MICRO but ~43 at EXTREME: at a fixed 4 iterations, peak density runs 1.23 ρ₀ at MICRO and 2.82 ρ₀ at EXTREME, so the top tier would simply be measuring a badly-solved fluid. Separately, displacement per step grows against a shrinking h, and at one step per frame the two largest tiers move particles 1.09 h and 1.38 h — past the radius their own neighbour list was built over. Substepping fixes both at once.
  • Under-relaxation ω = 0.75 with the per-iteration correction capped at 0.25·d. A Jacobi solver run to a fixed low iteration count overshoots the density constraint, and because PBD recovers velocity as v = (p − x)/Δt, that overshoot becomes permanent velocity jitter — a pool started at rest otherwise sits at ~18% of its released potential energy indefinitely. Damping the update drops the resting residual by ~250× while leaving the dam-break wave-front arrival time unchanged (0.72 s in both cases).
  • XSPH viscosity c = 0.12. Velocity is CFL-limited to 0.85·h/Δt.
  • Neighbour lists are capped at 96 entries against an observed peak of ~58. Exceeding the cap silently truncates the density sum, so saturation is a hard gate rather than a warning.
  • Boundary: hard positional clamp inside the closed tank each iteration, with a fixed per-particle sub-spacing offset to prevent lattice stacking. Containment is therefore structural, not impulse-based — leakage is impossible by construction, and the gate verifies it.

Determinism

  • Seeded mulberry32 PRNG; initial jitter and wall offsets are drawn once at init.
  • Fixed Δt, fixed iteration count, fixed step budget — the simulation never reads the clock.
  • Counting-sort spatial hash is stable; neighbor cells are visited in a fixed (z,y,x) order so floating-point summation order is identical every run.
  • No transcendental functions in the hot path (only sqrt, IEEE-exact).
  • State fingerprint = FNV-1a over positions quantised to 1/1024 m.

Measurement protocol

  • Warmup — tier-specific step count, fully simulated and rendered, discarded.
  • Measure — fixed step budget (identical work on every machine, so wall-time is the only variable).
  • Camera, viewport resolution and render mode are locked; the scene renders to an offscreen buffer at a fixed benchmark resolution and is blitted to the window, so window size cannot affect the score.
  • Total frame time = rAF-to-rAF wall delta (includes vsync/compositor wait). Effective frame time = max(CPU total, GPU) — the vsync-independent critical path used for scoring.
  • GPU time via EXT_disjoint_timer_query_webgl2; disjoint results are discarded. If unavailable the harness falls back to periodic sync-drain probes, which are excluded from frame-time statistics and clearly labelled.

Correctness gating

Density, kinetic energy and neighbour-budget statistics are accumulated on every step (folded into an existing pass, so the cost is identical on every machine and comparability is preserved). The gates test whole-run peaks, not the final frame, so a run that blows up mid-flight and then settles still fails. A run that trips any gate has its score withheld — timings remain visible but are marked informational only.

Score

SCORE = particles × measured_steps / effective_time / 1000 — kilo particle-steps per second. CPU score uses simulation time only; GPU score uses GPU render time only. Scores are withheld unless every correctness gate passes.

Compare like with like. Because each tier carries its own iteration count, a tier is a self-contained workload — the same way a graphics benchmark's 1080p and 4K presets are not compared to each other. A MICRO score is only meaningful against another machine's MICRO score. The workload.pairOpsPerStep field in the exported JSON gives the underlying kernel-evaluation count if you need a cross-tier work measure.
