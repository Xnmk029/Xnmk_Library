# 恢复与验证

只有存在 `COMPLETE.json`、其中 `unresolved_omissions` 为空的版本才是通过校验的备份。`waiting_for_idle`、`failed` 或没有 COMPLETE 的目录均为未完成版本。

版本内保存 `manifest.jsonl`（全部普通文件大小、源与目标 SHA-256、时间戳、目录和链接记录）、`source-map.json`、SQLite 清单、复制与重试事件日志、恢复抽样结果。先读取源目录映射，再恢复到一个**尚不存在的新目录**，不要覆盖现有工作区。

用本机 Python 执行：

```powershell
& '<python.exe 的完整路径>' '<版本目录>\restore_backup.py' '<版本目录>'
& '<python.exe 的完整路径>' '<版本目录>\restore_backup.py' '<版本目录>' --restore-to '<新的恢复目录>'
```

第一条逐个验证清单内的普通文件，第二条先验证，再复制并验证恢复结果。源目录不需要在线。四个源的相对路径映射保持不变。恢复时以清单为准；未完成版本续传期间，已从源移除的旧文件可能仍留在备份数据树中，恢复工具不会恢复这些未引用文件。全量文件校验比较普通文件的主数据流与 NTFS 备用数据流的大小和 SHA-256。备份以分块复制和前缀比对续传，保留隐藏、只读等基本属性；恢复通过 Windows 复制接口同时恢复各数据流。

链接不会在备份或自动恢复过程中激活。清单保存链接相对路径、原目标、symlink/junction 类型和是否指向登记范围之外；恢复工具输出 `restore-links.json`。恢复登记范围内的链接时，把原绝对根路径按 `source-map.json` 换为新根后，用 Windows `New-Item -ItemType SymbolicLink` 或 `Junction` 重建。相对链接保留相对目标。外部链接依赖内容不在本次登记范围内，须原依赖在线或单独恢复后再连接。不要对未检查的链接执行递归复制。

硬链接按独立普通文件保存；目录结构和文件内容可恢复，但不保证恢复原硬链接共用存储、ACL、所有者、压缩/稀疏存储方式或审计策略。目录时间戳和原属性保存在清单中。若遇到 EFS 加密文件，任务会失败并报告，需要另行保留证书及加密属性，不会静默解密后宣称完整。本次是工作区文件备份，不是操作系统镜像。

一致性证据：复制前两次全量清单一致；每个普通文件复制后比较源与目标大小和 SHA-256；最终再次逐文件核对，并再次扫描源变化。发生源变化就等待下一次空闲重新核对。没有使用 VSS，因此不声称所有文件来自同一原子时间点。

恢复抽样在每个非空源中选择一个文件，复制到版本内 `recovery-checks` 并比较 SHA-256；除此之外所有普通文件均执行全量读取与散列验证。
