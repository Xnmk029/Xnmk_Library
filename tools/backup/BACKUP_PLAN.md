# 完整工作区空闲备份任务

授权：用户要求在 Godot Bench run 搭建完成后，规划整个工作区备份，并空闲启动。此任务进行一次完整备份，完成后停止监控；当前不立即复制大型工作区。

默认目标：I:/Backups/benchmark-workspace。I: 与 F: 位于不同物理磁盘，已检查为 NTFS，当前约有 1.5 TB 可用。执行前再次校验磁盘在线、卷 ID 和空间。若用户随后指定其他目标，先更新计划。

## 范围

- F:/benchmark：全部工作区内容，包括 .git、隐藏文件、未提交与未跟踪文件、Git 忽略文件、素材、模型输出、录屏、图像、缓存、sandbox harness 和验收副本。
- F:/bench-runs：仓库外受测目录和全部交付。
- F:/bench-probes/godot-4.5.1：当前固定的便携 Godot 环境。
- 用户 APPDATA 下 BenchRuns：本次接入创建的 Godot 独立用户数据。

不按 git ls-files 筛选，不排除 node_modules、.godot、archives 或大型素材。工程收卷排除缓存的规则不适用于本次完整备份。

目录链接不递归跟随到未登记的外部目录；保留可恢复的链接本体/目标清单，另列外部依赖。无法读取或复制的条目必须报告，不能把有遗漏的备份标为完整。目标必须在所有源目录之外。

## 空闲启动

1. Godot 接入完成标记为 true；其他与 benchmark 相关的 Codex 聊天和 Bench jobs 没有在运行。
2. 使用 check_idle.ps1：当前 Windows 会话至少 15 分钟无键鼠输入，CPU 两次观测均不超过 15%；若可读取 GPU 使用率，不超过 10%；无活动 Godot 验收进程。
3. 备份前确认源目录处于稳定状态。等待期间只做轻量状态检查，保持安静；用户恢复操作或出现活跃任务时暂缓。

## 执行与恢复

先计算源文件数量、总大小、目标容量和链接清单。创建唯一时间戳版本目录，包含 sources/benchmark、sources/bench-runs、runtime/godot-4.5.1、userdata/BenchRuns；记录源目录映射。

使用后台隐藏窗口执行可续传复制，保留 Unicode 路径和相对结构。当前实现使用 Python 分块复制全部 NTFS 数据流，按源文件身份保存半成品；恢复时比对半成品前缀后继续。小型实测发现本机 CopyFileEx 中止行为不能可靠保留可续传目标，因此没有采用该方式。不使用 /MIR、/PURGE，不删除源文件，不覆盖已完成版本。系统文件锁防止重复启动；空闲条件结束时暂停，并在下次空闲继续同一未完成版本。

记录每个复制进程、退出码、错误与重试。复制后核对全部普通文件的大小与 SHA-256、相对路径和链接记录；源文件在扫描、复制或验证期间变化时重新复制并核对，保存版本不一致记录。只有全部范围成功、无未解决遗漏且验证通过才能写 complete 标记。

## 交付

- 版本目录、源/目标清单、全部文件 SHA-256、链接与外部依赖清单。
- 复制日志、校验结果、失败/重试记录、总体积和完成时间。
- 恢复说明和若干恢复读取检查；保留所有未完成版本和已有完整版本。

固定入口 `tools/backup/status.json` 是静态定位文件。权威运行状态保存在计划 `state_directory` 的 `status.json`，复制、失败、重试日志保存在同目录 `events.jsonl`，首次执行计划及轻量检查为 `execution-plan.json` 和 `first_check.json`。控制目录位于 F:/benchmark-backup-state/01a12ab3-8f2e-7b00-8b31-597a3d19188c，处于四个源目录之外，避免日志不断变化影响源校验。完成时版本目录保存日志和清单快照。

后续执行必须遵照同目录 `RUNBOOK.md`：每次启动前、运行期间每 30 秒以内调用 list_threads 并刷新 75 秒有效的运行许可；监控停止刷新时后台自动暂停。首次只初始化，实际扫描由后续空闲心跳开始。完成通知只报告目标、体积、文件数和验证结论。等待或无变化时不发重复通知；完成后停用本次空闲监控。
