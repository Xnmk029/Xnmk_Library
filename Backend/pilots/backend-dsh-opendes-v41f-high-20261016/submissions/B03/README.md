# 目录重复文件检测器

只读的重复文件检测器：扫描指定根目录内的普通文件，用真实 SHA-256 判断哪些文件字节完全相同。
**不做删除、移动或任何自动清理**，也不跟随符号链接与 junction。

## 运行

```bash
node server.js --port 8000 --data ./data --root ./demo
```

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--port` | `8000` | 监听端口，服务只绑定 `127.0.0.1` |
| `--data` | `./data` | 数据目录，不存在则创建，重启后复用 |
| `--root` | `./demo` | 被扫描的根目录；根内只能是普通文件参与比对 |

启动后打开 <http://127.0.0.1:8000/>。要求 Node.js 24，仅使用原生模块，无第三方依赖，无需安装步骤。

## 网页

- **启动扫描**：点击「启动扫描」调用 `POST /api/scan`，等待扫描完成后直接展示结果。
- **查看进度**：扫描期间每 400 ms 轮询 `GET /api/scan`，显示当前阶段（遍历 / 计算哈希）与 `已处理/总数`。
- **展开重复分组**：每组显示真实 SHA-256、字节大小与文件份数，展开后列出根目录相对路径。
- **查看上次结果**：`GET /api/result` 返回最近一次完整结果；服务重启后由数据目录恢复，页面刷新即可看到。
- 所有展示都来自真实接口响应，页面不使用浏览器缓存代替服务端状态。

## 接口

### `GET /health`

```json
{ "ok": true }
```

### `POST /api/scan`

启动扫描并等待完成，返回最近一次完整结果：

```json
{
  "groups": [
    { "sha256": "9f86d0818…", "size": 12, "paths": ["a.txt", "sub/b.txt"] }
  ],
  "scanned": 7,
  "skipped": 2
}
```

- `paths`：相对根目录的路径数组，按字符串字典序排序；`groups` 按每组首个路径排序。
- 只有字节完全相同且至少两份的文件才归为一组；**零字节文件同样可以重复**。
- 仅凭文件大小或文件名绝不判重复，大小只用作免读哈希的低成本预筛（大小唯一者不可能有第二份）。
- `scanned`：成功读取的文件数。`skipped`：无法读取或超过单文件上限（8 MiB）的文件数。
- 并发扫描请求合并到同一次运行；检查与启动之间没有 `await`，因此不会并发启动第二次扫描，也不会发布半份结果。
- 扫描失败返回非 2xx 与 `{"error":"原因"}`。

### `GET /api/scan`

当前状态与进度，供网页轮询：

```json
{
  "running": true, "phase": "hashing", "root": "…\\demo",
  "files": 12, "hashed": 4, "total": 9, "sizeGroups": 3,
  "startedAt": "…", "finishedAt": null,
  "scanned": 3, "skipped": 1, "groupCount": 0, "error": null
}
```

`phase` 为 `idle` / `walking` / `hashing`。另外附带 `unreadable`、`oversize`、`uniqueSize`、`uniqueHash` 四项诊断计数，便于排查为什么某个文件没有进入结果（不计入 `skipped`）。

### `GET /api/result`

最近一次**完整**扫描结果，字段同 `POST /api/scan`，另含 `finishedAt` 与 `persisted`。
扫描进行中时返回的是上一次落盘的结果而不是半成品；从未扫描过则返回 404 与 `{"error":"尚未完成过扫描"}`。

## 行为与边界

- **只读**：只调用 `readdir` / `realpath` / `lstat` / `readFile`，除数据目录（结果 JSON）外不写任何文件。
- **不跟随链接**：`readdir` 返回的符号链接条目直接跳过；目录还会做 `realpath` 校验，真实路径必须仍在根目录内，并跳过重复访问过的真实目录，因此 junction / 目录符号链接无法把扫描带出根外，也不会造成循环。
- **根外路径不可读取**：扫描始终从 `--root` 出发，结果中的路径是相对根目录的路径，不接受任何来自请求的路径参数。
- **大小上限**：单个文件超过 8 MiB 计入 `skipped` 且不读取；读取后再次校验长度。
- **零字节文件**：正常参与比对，多个空文件会组成 `size: 0` 的重复组。
- **中文文件名**：路径按 UTF-8 原样返回与展示。
- **持久化**：结果以 `last-result.json` 原子写入（先写临时文件再 `rename`）到数据目录，因此重启后仍在，且不会留下半份结果。
- **非 2xx 错误**：所有错误响应形如 `{"error":"原因"}`；未知路径返回 404，方法不符返回 405。

## 演示数据示例

在 `--root` 目录下放入：

| 文件 | 内容 |
| --- | --- |
| `同名不同内容/报告.txt` | `版本 A` |
| `同名不同内容/子目录/报告.txt` | `版本 B` |
| `不同名相同内容/一.txt`、`不同名相同内容/二.txt` | 同一段文本 |
| `空文件/空一`、`空文件/空二` | 空 |
| `中文名/重复的文档.txt`、`中文名/副本/重复的文档.txt` | 同一段文本 |

预期：`报告.txt` 两份因内容不同而**不**成组；其余三组各按真实 SHA-256 成组（空文件组 `size` 为 0）。
改动任一文件后再次点击扫描，结果会随内容更新。
