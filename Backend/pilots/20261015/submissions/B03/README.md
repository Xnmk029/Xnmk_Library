# 目录重复文件检测器

仅需 Node.js 24，无第三方依赖。

```powershell
node server.js --port 3000 --data "F:\inspector-data" --root "F:\files-to-check"
```

打开 http://127.0.0.1:3000 。服务只监听 `127.0.0.1`。参数省略时端口为 3000，根目录为当前目录，数据目录为当前目录下 `.duplicate-inspector`。根目录必须已经存在，数据目录自动创建。建议数据目录放在扫描根目录之外；根目录内已有的服务数据文件也属于扫描范围。

点击“开始扫描”，可查看枚举、读取和保存进度，展开分组查看相对路径及真实 SHA-256。“查看上次完整结果”从服务器重新读取结果；重启服务后仍可查看。文件名按纯文本显示。网页不提供删除、移动或清理功能。

- `GET /health` → `{"ok":true}`。
- `POST /api/scan` → 等待扫描完成，返回 `{groups:[{sha256,size,paths}],scanned,skipped}`。并发请求共享同一次扫描。
- `GET /api/result` → 最近一次完整结果；首次扫描前为空结果。
- `GET /api/status` → 当前阶段、成功数、跳过数、已发现文件总数及根目录。枚举结束后总数才固定。
- 错误使用非 2xx 状态及 `{"error":"原因"}`。扫描根目录只由启动参数决定，API 不接受路径参数。

递归扫描普通文件，忽略符号链接、junction 和特殊文件；根目录及其祖先也不能是链接。不可读、超过 8 MiB 或读取期间检测到变化的文件计入 skipped，成功完整读取的文件计入 scanned。恰好 8 MiB 和空文件均支持。目录无法枚举时整次扫描失败，保留旧结果。

文件先计算 SHA-256，再逐字节确认，只有至少两份内容相同才输出分组。路径统一使用 `/`，路径与分组均按字符串字典序排序。扫描期间在数据目录保存私有临时内容快照，内存占用不随文件内容总量增长，临时磁盘空间最多约为本次扫描不同内容的总大小；正常完成或失败后清理。结果先写临时文件、同步后原子替换 `result.json`，不会发布半份结果。不要让多个服务进程共用同一数据目录。

扫描不是文件系统事务快照。建议扫描期间保持目录稳定；扫描后修改文件，再次扫描即可更新结果。实现检查链接、真实路径和打开文件的身份，但 Node 原生跨平台接口无法完全消除其他进程恶意并发替换目录所产生的竞态。

运行集成验证（自动创建并清理工作目录内的测试样例）：

```powershell
node --test test.js
```

样例包含同名不同内容、不同名相同内容、空文件、中文文件名、8 MiB 边界及超限文件，并验证并发扫描、更新、重启恢复和 junction 隔离。

`demo-files` 已提供 6 个演示文件：两份同名不同内容、两份不同名相同内容，以及两个空文件。可运行：

```powershell
node server.js --port 3000 --data .demo-data --root demo-files
```

首次扫描应读取 6 个文件、跳过 0 个、得到 2 组。修改 `demo-files/中文副本.txt` 的内容后再次扫描，应只剩空文件分组。
