# 离线协同文本编辑器

实现两个浏览器客户端可协同编辑的纯文本笔记服务。客户端断网后仍可编辑，重连同步；服务重启后已确认操作保留。提供编辑区和操作历史视图，清楚区分本地待同步、服务已确认和远端已接收状态。

## 数据与行为契约

范围仅限纯文本插入与删除，不要求富文本、多人光标或账号体系。每个操作有稳定 client_id、单调序号和因果上下文；重传同一操作不能重复应用。以 Unicode 码点为基本单位，不能拆坏代理对。同一锚点的并发插入必须按公开且确定的规则排序；删除只能删除操作创建时可见的目标字符，不能吞掉未见过的并发插入。选用 CRDT 或 OT，但需公开完整冲突语义，并实际实现核心合并逻辑。

## 交付要求

可开两个独立浏览器上下文的编辑器、同步服务、持久操作记录、断连控制和导出功能。可以使用 WebSocket 库，不允许直接把完整协同引擎当作核心实现。离线操作须持久化到客户端，刷新后仍可同步。

## 运行与交付契约

使用 Node.js 24 原生模块，不安装第三方依赖，不生成 node_modules。交付 server.js、界面和 README；可拆分普通文件。启动为 node server.js --port <端口> --data <数据目录>，额外参数见各题。所有服务仅监听 127.0.0.1；GET /health 返回 JSON {"ok":true}，GET / 提供可操作界面。数据目录不存在时创建；重启指使用同一目录重新启动。JSON 响应 Content-Type 正确，错误返回非 2xx 与 {"error":"原因"}；响应不能假装成功。界面从真实 API 获取结果，能完成题述演示，不能用随机数或固定样例模拟后端状态。用户提供的文本按纯文本展示。

交付不包含 TODO、未实现分支或需用户补充的核心逻辑。README 写明启动方式和操作流程。用到的样例数据由程序或用户在本地生成，不依赖账号、网络服务或其他项目文件。

## HTTP/CLI 接口

GET /api/docs/<docId> 返回 {text,operations,characterIds,pending}；POST /api/docs/<docId>/ops 接收 {operations:[...]} 并返回同结构。插入操作 {opId,clientId,seq,type:"insert",after,text}，after 为 ROOT 或字符 ID；每个插入字符的 ID 是 opId+":"+码点偏移（从 0 开始）；多字符插入形成连续链，首字符挂到 after。同一锚点的子树按字符 ID 的 Unicode 码点字典序遍历（深度优先），ROOT 本身不显示。删除操作 {opId,clientId,seq,type:"delete",targetIds:[...]}，仅把指向的字符标记为删除，后代仍显示。重复 opId 且载荷相同幂等，不同载荷 409。未知锚点的插入进入 pending，依赖到达后应用；未知删除目标保留 tombstone，目标到达后不显示。operations 包含已接收的唯一操作。界面有文档 ID、编辑区、离线/在线按钮和操作历史；离线编辑持久化在客户端，再次上线真实同步。
