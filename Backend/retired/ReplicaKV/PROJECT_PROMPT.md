# 三节点键值服务与故障演练台

实现三个独立进程组成的持久化键值服务，以及展示角色、任期、复制进度和请求结果的演练台。支持 put/get/delete，停止当前主节点后重新选主；网络分区时少数派不能确认写入，恢复后自动追平。

## 数据与行为契约

固定三节点，不要求动态成员变更、拜占庭容错或跨地区部署。采用 Raft 或其他明确满足本题语义的共识方案；实现核心选主、日志复制和恢复，不能直接调用现成共识服务。写入成功表示已在多数派持久化并提交；相同 request_id 重试幂等。读取必须满足线性一致性，无法确认安全读取时返回不可用，不能由失去多数派的旧主返回成功的陈旧值。客户端超时表示结果未知，可凭 request_id 查询或重试，不能当作必然失败。

## 交付要求

三个真实节点、独立数据目录、客户端 API、可观测界面和受控故障代理。停机与分区由评测器或外部进程实施；界面上的“断开”按钮必须映射真实连接故障。资源档建议 3 节点、3 客户端、1,000 次操作、值大小不超过 4 KiB，最终阈值需在固定机器上校准。

## 运行与交付契约

使用 Node.js 24 原生模块，不安装第三方依赖，不生成 node_modules。交付 server.js、界面和 README；可拆分普通文件。启动为 node server.js --port <端口> --data <数据目录>，额外参数见各题。所有服务仅监听 127.0.0.1；GET /health 返回 JSON {"ok":true}，GET / 提供可操作界面。数据目录不存在时创建；重启指使用同一目录重新启动。JSON 响应 Content-Type 正确，错误返回非 2xx 与 {"error":"原因"}；响应不能假装成功。界面从真实 API 获取结果，能完成题述演示，不能用随机数或固定样例模拟后端状态。用户提供的文本按纯文本展示。

交付不包含 TODO、未实现分支或需用户补充的核心逻辑。README 写明启动方式和操作流程。用到的样例数据由程序或用户在本地生成，不依赖账号、网络服务或其他项目文件。

## HTTP/CLI 接口

每个节点启动 node server.js --id n1 --port <端口> --data <独立目录> --peers n2=http://127.0.0.1:端口,n3=http://127.0.0.1:端口。可追加内部 API，但所有节点间流量必须使用 peers 给定的目标 URL（可能是故障代理，禁止绕过）。GET /api/status 返回 {nodeId,role,term,leaderId,commitIndex}，role 为 leader/follower/candidate。POST /api/kv 接收 {requestId,key,value}，value 为字符串或 null（删除），多数派持久提交后返回 200 {ok:true}。重复 requestId 同载荷幂等，不同载荷 409。GET /api/kv/<key> 线性一致地返回 {value}（不存在用 null）；跟随者可用 307/308 指向已知主节点，无法安全处理返回 503；旧主失去多数派时不得返回成功。界面显示状态并可写入、读取，进程终止由外部实施。读写超时最迟 2 秒返回失败/不可用，不能无限挂起。
