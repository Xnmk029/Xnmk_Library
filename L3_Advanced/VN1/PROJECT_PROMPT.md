# NORINCO VN1 8×8 轮式步兵战车家族
## 公开资料考证级 WebGPU 程序化建模、PBR 材质与专业渲染应用
---
## 0. 总体目标与真实性原则
构建一套基于 Web、HTML 与 WebGPU 的单页交互式三维应用，对中国 NORINCO 面向国际市场推出的 **VN1 8×8 轮式步兵战车及其公开确认的家族改型**进行高精度、可追溯、图片对照级程序化复现。

本项目定位不是科幻化军武概念设计，而是：

> **公开资料驱动的装甲车辆数字考证、程序化建模与 PBR 可视化系统。**

所有车体比例、炮塔构型、武器站、观察装置、舱口、轮组、涉水推进装置、客户国配置及任务改型，均必须通过公开照片、厂商展会资料、交付影像或可信防务资料交叉确认。

严禁为了“看起来复杂”而虚构未公开的装甲厚度、内部管线、火控结构、弹药数量、动力参数、电子设备型号或主动防护系统。

# 1. 资料检索、考证与证据管理

## 1.1 资料优先级

建模前必须建立资料来源清单，优先级如下：

1. NORINCO 或中国兵器工业集团公开展会资料、产品手册与宣传影像；
2. 中国国防部、客户国国防部、军方交付及阅兵影像；
3. IDEX、珠海航展、Defense & Security Thailand 等防务展公开照片；
4. 高分辨率实车绕拍、交付仪式照片、训练及涉水影像；
5. Janes 等专业防务媒体；
6. Army Recognition、Defence Web 等可核对图片来源的专业媒体；
7. 二手数据库、论坛和社交媒体只能用于发现图片线索，不得单独作为关键结构结论的依据。

不得把游戏模型、比例模型、CG 宣传图、未经标注的网友复原图当作实车结构证据。

## 1.2 证据等级

为每项建模特征建立内部“证据账本”：

* **A 级——确认特征**：至少有官方资料或多个独立高清视角支持；
* **B 级——高可信推定**：可从实车照片确认总体形态，但尺寸或工作方式没有公开；
* **C 级——示意复原**：只知道功能区或大致位置，缺少足够资料；
* **禁止复原**：涉及未公开的装甲剖面、火控算法、通信系统内部结构或无法验证的机械细节。

界面必须允许显示：

* 特征名称；
* 所属车型；
* 证据等级；
* 资料来源；
* 观察角度；
* 已确认部分；
* 推定部分；
* 不确定性说明。

C 级结构必须使用中性灰色、半透明材料或“示意结构”标签，不得以确定事实方式展示。

## 1.3 型号命名约束

严格区分：

* 中国人民解放军自用的 **08式轮式装甲车族/ZBL-08 系列**；
* 面向出口的 **VN1 家族**；
* 客户国实际采用的 VN1 配置；
* 在展会上展示但没有证据证明已经交付的选配模块。

不得因为底盘具有技术关联，就把中国自用型的炮塔、传感器、装甲或内部设备直接复制到出口型 VN1。

“VN1C”等名称在不同公开报道中可能存在用法差异。界面建议采用：

> **泰国型 VN1——UW4B 遥控武器站构型**
> 补充注释：部分公开报道将其称为 VN1C。

除非找到厂商或客户国官方型号文件，否则不得把二手资料中的名称标记为绝对官方名称。

# 2. 运行环境与交互架构

## 2.1 技术基准

* 基于 Web 与 HTML 运行；
* 使用 WebGPU 作为底层图形渲染管线；
* 交付为可独立运行的单页完整应用；
* 几何体、蒙皮骨架、材质、程序纹理、地形和粒子均由代码生成；
* 严禁加载 `.gltf`、`.glb`、`.obj`、`.fbx` 等外部三维模型；
* 不依赖外部在线三维资产或商业材质包；
* 程序纹理必须使用固定随机种子，确保结果可复现；
* WebGPU 不可用时显示清晰的兼容性提示，不静默退化为错误画面。

允许通过代码生成：

* 参数化网格；
* SDF/CSG 组合几何；
* 曲线扫描生成的管线与扶手；
* 程序化法线、粗糙度、污渍和磨损纹理；
* 文字、编号和警示标识贴花；
* 程序化天空、环境立方体贴图及摄影棚灯板。

## 2.2 模块化 UI

应用必须使用现代化专业界面，将功能划分为相互隔离的标签页：

1. **[全车装配检视]**
2. **[家族改型与客户构型]**
3. **[舱内布局与乘员战位]**
4. **[PBR 材质与服役磨损]**
5. **[专业渲染工作室]**
6. **[资料来源与考证状态]**

每个页面保存独立的相机、灯光、材质和显示状态。切换页面时不得覆盖其他页面的参数。

# 3. 核心任务：VN1 图片对照级程序化建模

## 3.1 底盘与车体

以 VN1 出口型 8×8 轮式装甲底盘为基准，重点复现：

* 八轮全驱底盘，每侧四个大直径轮胎；
* 前部楔形车体；
* 驾驶员位于车体前部左侧；
* 动力舱位于车体前部右侧；
* 炮塔或遥控武器站位于车体中部；
* 后部载员舱；
* 后部上下车坡道或尾门结构；
* 车顶舱口、潜望镜、通风装置和天线基座；
* 车体侧面装甲板、储物箱、踏板、扶手和工具固定装置；
* 前部灯组、牵引环、防浪板及挡泥板；
* 后部双水上推进装置及相关开口；
* 轮胎中央充放气接口、轮毂、转向连杆可见部分与挡泥结构；
* 车体焊缝、装甲板接缝、螺栓、检修盖和排水孔。

不得把 VN1 建模成履带式车辆，也不得保留 VT-4 的六对负重轮、履带、主战坦克炮塔、125mm炮、自动装弹机或车体后部动力舱结构。

## 3.2 尺寸与比例重建

优先采用已公开的整车尺寸和战斗全重资料。对于缺乏可靠数值的局部尺寸：

* 使用多视角照片透视校正；
* 以轮胎直径、车体总长、总宽或已知武器口径作为比例标尺；
* 至少使用正侧、正前、正后和顶部斜视照片交叉验证；
* 避免从单张广角照片直接反推精确比例；
* UI 中将测量结果标记为“公开数值”或“影像估算”；
* 影像估算尺寸不得伪装成毫米级官方数据。

## 3.3 车轮、悬挂与转向

程序化构建：

* 八个独立车轮总成；
* 轮胎胎面、胎侧文字区域、轮辋、轮毂和紧固件；
* 前部转向轮合理的转角联动；
* 悬挂压缩和车体俯仰；
* 轮胎接地形变；
* 轮胎与地面的接触阴影；
* 中央轮胎充放气系统的可见外部连接特征；
* 轮胎破损或缺气演示模式，但不得将其设为默认外观。

悬挂内部形式若无法从公开资料确认，只复原外部可见结构和符合车辆运动学的简化机构，不虚构完整内部液压回路。

# 4. 武器系统与观瞄设备

## 4.1 基准型 VN1 步兵战车构型

根据公开实车资料复现：

* 30mm级机关炮；
* 炮口、炮管支撑结构和防振框架；
* 7.62mm级并列机枪；
* 炮塔正面和侧面的装甲外形；
* 炮手瞄准装置；
* 炮塔舱口、观察镜、烟幕弹发射器；
* 经照片确认后才可安装的 HJ-73C/D 系列反坦克导弹发射导轨；
* 火炮俯仰及炮塔旋转动画；
* 炮管不得穿过车体、舱盖或其他部件。

导弹只能作为对应照片或展会构型的可选模块。不得默认认为所有出口车辆均装备导弹。

## 4.2 泰国型 VN1——UW4B 遥控武器站

重构泰国实际公开影像中出现的 UW4B 遥控武器站，包括：

* 无人化或遥控炮塔外形；
* 30mm级机关炮；
* 并列机枪；
* 武器站光电观瞄模块；
* 烟幕弹发射器；
* 炮塔座圈和车内操作员位置；
* 对公开照片可确认的外部附属设备进行复原。

必须区分：

* 武器站在试验或展会中被展示过的武器兼容能力；
* 泰国实际交付车辆照片中真正安装的武器。

如果交付影像中没有出现反坦克导弹发射器，不得擅自安装。可在 UI 中将其列为“公开展示过的武器站选项”，但不能标记为“泰国服役标准配置”。

## 4.3 射击表现限制

允许制作纯展示性的：

* 炮塔旋转；
* 火炮俯仰；
* 炮口短暂火焰与烟尘；
* 抛壳或机构后坐的视觉动画；
* 光电设备转动；
* 烟幕弹发射视觉效果。

不得提供弹道计算器、弱点分析、实战瞄准解算、毁伤模拟或可用于现实武器操作的精确射表。

# 5. 家族改型与客户构型考证

在 **[家族改型与客户构型]** 页面提供并排比较、差异高亮和部件树切换。

## 5.1 VN1 标准外贸步兵战车型

作为基础模型，保留：

* 8×8 两栖底盘；
* 中部有人炮塔；
* 30mm级机关炮；
* 并列机枪；
* 三名车组与后部步兵载员舱；
* 经资料确认的导弹导轨作为可选模块；
* 双水上推进装置；
* 基础型车体储物及防浪板。

## 5.2 泰国型 VN1 / UW4B 构型

外形差异重点包括：

* UW4B 遥控武器站；
* 不同于基准有人炮塔的座圈、外壳和光电设备；
* 泰军涂装、编号、国籍标识及警示标识；
* 根据交付批次照片确认的天线、储物箱、挡泥板和车外附件；
* 不得将不同交付批次的附件混合成一辆不存在的“终极版本”。

## 5.3 加蓬型 VN1

依据公开阅兵及交付影像重构：

* 有人炮塔；
* 30mm级机关炮与炮管支撑结构；
* 并列机枪；
* 经影像确认的导弹导轨；
* 加蓬车辆的迷彩、编号和外部设备布局。

若加蓬车辆与标准外贸型仅存在涂装和少量附件差异，应如实标记为“客户构型”，不得夸大为全新技术改型。

## 5.4 委内瑞拉海军陆战队构型

以公开实车照片为依据，提供：

* 海军陆战队涂装与国籍标识；
* 对应批次的炮塔和武器配置；
* 车辆编号与外部携行物；
* 两栖状态展示。

没有足够证据时，不得为其增加专属装甲、动力升级或特殊火控系统。

## 5.5 VN1 家族任务改型

以下车辆属于同底盘家族任务型，不应全部标记为“步兵战车”：

* **VS27 装甲救援车**：复原公开可见的吊臂、绞盘、工具箱和救援设备；
* **SM4A 120mm自行迫击炮**：复原公开确认的迫击炮上装和车顶结构；
* **VE36 指挥车型**：重点表现增设天线、通信舱和车体上层结构，但不得虚构通信设备内部参数；
* **VN1 救护车型**：表现增高舱体、医疗标识及内部担架位置；
* 其他任务改型仅在获得充分公开图片后开放。

各改型必须通过“模块替换”实现，而不是简单在基准车型上叠加零件。

## 5.6 差异比较工具

支持：

* 左右分屏；
* 重叠轮廓比较；
* 差异区域热区高亮；
* 部件新增、移除、位移和尺寸变化统计；
* 同一视角、焦距和灯光锁定；
* 客户构型时间线；
* 证据等级筛选；
* “仅显示已确认结构”模式。

# 6. 舱内布局与乘员战位

## 6.1 基本布局

根据公开资料与可见舱内照片，重构：

* 前左驾驶舱；
* 前右动力舱；
* 中部炮塔或遥控武器站操作区；
* 后部载员舱；
* 后部坡道或尾门；
* 车顶舱口；
* 载员座椅、安全带、扶手和地板防滑结构；
* 驾驶员方向盘或转向操纵机构；
* 仪表与显示终端的外形；
* 潜望镜和观察装置；
* 炮手、车长或武器站操作员工作位置。

不得沿用 VT-4 的三人坦克战斗舱、炮塔吊篮、125mm炮尾、盘式自动装弹机或坦克弹药架。

## 6.2 动力舱

公开资料支持的情况下，可建立 VN1 前右动力包的简化展示模型：

* 柴油发动机外部轮廓；
* 传动系统外壳；
* 冷却器、风扇和进排气通道；
* 可见检修盖对应关系；
* 动力包与驱动轴的功能性示意。

发动机型号、功率与传动细节必须显示来源及可信度。若不同资料互相冲突，则显示范围或争议说明，不选择其中一个数值冒充定论。

缺乏实物照片的内部管路不得逐根“精确还原”。可以用简化管线表达功能关系，但必须标注为工程示意。

## 6.3 载员舱

根据具体构型处理乘员容量，不将所有版本固定为同一人数。基准有人炮塔型可按公开资料建立三名车组与七名载员的布局，但必须考虑炮塔吊篮或座圈对舱内空间的影响。

复现：

* 独立防冲击座椅；
* 载员面向与腿部空间；
* 武器及个人装备固定点；
* 坡道开启后的下车通道；
* 顶部舱口逃生路径；
* 灭火器和常见安全设备；
* 舱内照明。

不可用互相穿插的人体模型掩盖空间矛盾。

## 6.4 人员模型

建立具有基础骨架和合理人体比例的：

* 驾驶员；
* 车长；
* 炮手或武器站操作员；
* 七名以内的步兵载员，人数随具体构型变化。

人员配备现代装甲兵或机械化步兵头盔、通信耳机、防护服和基本携行装具。服装与国籍构型对应，避免把中国、泰国、委内瑞拉和加蓬装备混用。

支持：

* 坐姿；
* 操作姿势；
* 开舱观察；
* 上下车；
* 舱内空间碰撞检查。

# 8. PBR 材质系统

## 8.1 着色模型

使用基于物理的金属度—粗糙度工作流：

* Cook–Torrance BRDF；
* GGX/Trowbridge-Reitz 法线分布；
* Smith 几何遮蔽；
* Schlick Fresnel；
* 能量守恒；
* Image-Based Lighting 或程序化环境光照；
* 多重散射能量补偿；
* 线性色彩空间计算；
* ACES 或同等级电影级色调映射。

纹理通道包括：

* Base Color；
* Metallic；
* Roughness；
* Normal；
* Height；
* Ambient Occlusion；
* Curvature；
* Cavity；
* Edge Wear Mask；
* Dust/Mud Mask；
* Oil/Grease Mask；
* Decal Mask。

颜色纹理使用 sRGB；金属度、粗糙度、法线、高度和遮蔽数据使用线性采样。

## 8.2 材质分类

至少建立以下独立材质：

1. 涂漆轧制装甲钢；
2. 焊缝及热影响区；
3. 炮管与机加工钢件；
4. 未涂装紧固件；
5. 橡胶轮胎；
6. 轮辋与轮毂；
7. 防滑涂层；
8. 光学玻璃；
9. 潜望镜与观瞄窗口的镀膜玻璃；
10. 灯具透明罩；
11. 帆布、防尘罩与织物；
12. 塑料和复合材料外壳；
13. 排气口及受热金属；
14. 舱内涂层、地板和座椅织物；
15. 泥土、砂尘、油污与潮湿层。

不得用同一套“军绿色金属材质”覆盖所有部件。

## 8.3 微表面细节

程序化生成：

* 细微橘皮漆面；
* 喷涂厚度差异；
* 轻微板材起伏；
* 焊缝纹理；
* 机加工方向纹；
* 橡胶胎面微裂纹；
* 防滑层颗粒；
* 光学镀膜颜色偏移；
* 排气热变色；
* 灰尘颗粒和雨水流痕。

微表面法线必须控制强度，避免把装甲钢表现成岩石或铸铁疙瘩。

# 9. 材质边缘磨损与服役旧化

## 9.1 基于物理位置的磨损生成

磨损不能使用均匀随机噪声覆盖全车。应综合：

* 网格曲率；
* 凸边暴露程度；
* 环境遮蔽；
* 人员接触频率；
* 开合运动；
* 行驶方向；
* 泥水飞溅方向；
* 重力方向；
* 轮胎旋转方向；
* 热源距离；
* 部件材质；
* 维护状态。

建立可调参数：

* 车辆服役时间；
* 环境干湿度；
* 沙漠/热带/兵营环境；
* 行驶距离；
* 清洗程度；
* 保养水平；
* 降雨量；
* 泥浆厚度；
* 漆层磨损强度；
* 金属氧化程度。

## 9.2 合理的磨损位置

较明显的磨损应集中于：

* 舱口边缘；
* 上下车踏板；
* 扶手；
* 尾门和坡道接触区；
* 工具固定架；
* 牵引环；
* 储物箱锁扣；
* 轮毂外缘；
* 挡泥板边缘；
* 炮塔或武器站维护盖；
* 车体低位受砂石冲击区域。

大面积装甲板中央只允许出现轻微擦痕、积尘、雨痕和局部褪色，不应布满均匀银色划痕。

## 9.3 边缘掉漆层次

掉漆至少分为：

1. 表层颜色轻微磨亮；
2. 底漆暴露；
3. 局部深色钢材暴露；
4. 极少量初期氧化。

暴露钢材不应全部呈现高亮银色。现役维护良好的车辆不得生成废弃车辆式重锈、贯穿腐蚀或大面积剥落。

## 9.4 不同材质的旧化差异

* **橡胶轮胎**：胎面抛光、灰尘嵌入、侧壁轻微龟裂，不出现金属掉漆；
* **光学玻璃**：轻微灰尘、水渍和擦拭痕，不应用金属粗糙度；
* **炮管**：局部油膜、烟尘、热影响，不生成夸张锈斑；
* **排气区**：高温变色、干燥烟灰和积尘；
* **防滑层**：凸点磨平、泥土填充凹隙；
* **帆布与防尘罩**：褶皱、褪色和边缘磨毛；
* **舱内高频接触面**：漆面磨亮，但整体保持军用维护状态。

## 9.5 旧化预设

提供：

* 展会新车；
* 新交付状态；
* 兵营日常训练；
* 干燥沙场训练；
* 热带高湿环境；
* 涉水后状态；
* 轻度长期服役。

默认状态为“正常训练使用、维护良好”，避免过度末日化。

# 10. WebGPU 专业渲染工作室

## 10.1 双模式渲染

### 实时预览模式

* 目标 60 FPS；
* 延迟渲染或 Forward+；
* 集群灯光剔除；
* 阴影级联；
* SSAO/GTAO；
* TAA；
* 动态分辨率；
* LOD；
* GPU 实例化；
* 视锥和遮挡剔除。

### 高质量累积模式

视口静止后自动进入：

* WebGPU 路径追踪或多帧累积；
* 多重间接光；
* 软阴影；
* 精确接触遮蔽；
* 景深；
* 运动关闭后的渐进式降噪；
* 火花点抑制；
* 收敛进度显示；
* 相机或材质变化时正确重置累积缓冲。

不得把普通后处理锐化冒充路径追踪。

## 10.2 专业相机

支持：

* 轨道环视；
* 自由飞行；
* 转台模式；
* 正交工程视图；
* 前、后、左、右、顶部及三分之四预设机位；
* 焦距/FOV；
* 光圈；
* 对焦距离；
* 快门；
* ISO；
* 曝光补偿；
* 传感器尺寸；
* 景深；
* 白平衡；
* 镜头畸变；
* ACES 色调映射；
* 高光压缩与阴影提升。

## 10.3 环境预设

由于应用不得依赖外部素材，环境优先采用程序化生成：

* 正午干燥沙场；
* 阴天兵营；
* 热带湿润训练场；
* 中性灰摄影棚；
* 黑色高反差产品摄影棚；
* 日落逆光环境。

每个环境包含：

* 程序化天空；
* 太阳或面积光源；
* 地面反射；
* 环境雾；
* 色温；
* 风向；
* 尘土浓度；
* 对应的曝光预设。

若使用内嵌 HDR 环境数据，必须随单页应用一起交付，并明确其授权与来源。

## 10.4 地面与粒子

纯代码生成：

* 沙砾、硬土和混合泥土地面；
* 微地形起伏；
* 轮胎压痕；
* 转向拖曳痕；
* 积水和湿润区域；
* 车轮接触处的轻微扬尘；
* GPU 驱动尘埃粒子；
* 低速与高速状态不同的颗粒运动；
* 粒子与车体深度遮挡。

轮胎印迹必须与八轮位置、轴距、转向角和行驶路径对应，不得使用履带压痕。

# 14. 最终验收标准

项目只有同时满足以下条件才算完成：

1. 一眼可识别为 VN1 8×8 出口型轮式装甲车辆；
2. 不残留 VT-4 的履带、125mm炮、坦克自动装弹机或后置动力舱逻辑；
3. 八轮、车体、炮塔、尾门和水上推进装置比例合理；
4. 泰国 UW4B 构型与有人炮塔构型能够明确区分；
5. 客户国涂装与结构附件不被随意混用；
6. 家族任务车型名称和功能分类准确；
7. 内构明确区分“公开确认”“影像推定”和“工程示意”；
8. PBR 材质在不同光照下保持物理一致性；
9. 边缘磨损与积尘遵循真实使用位置，而非均匀噪声；
10. 实时预览与高质量累积渲染均能实际运行；
11. 4K/8K 导出功能可用；
12. 所有重要军事知识结论均可追溯到公开来源；
13. 找不到可靠资料时宁可简化、隐藏或标注未知，也不得凭空补齐。

最终成果应呈现为：

> **一套以公开证据为基础、能够对 VN1 实车构型进行辨析，同时具备专业 PBR 材质、合理服役磨损和商业级 WebGPU 渲染表现的交互式数字军武考证应用。**
