## 2. 关键技术决策

### 2.1 CDN 选择与兜底
- 主 CDN：`https://cdn.jsdelivr.net/npm/three@0.149.0/build/three.min.js`（UMD）
- 兜底 1：`unpkg.com/three@0.149.0/build/three.min.js`
- 兜底 2：`cdnjs.cloudflare.com/ajax/libs/three.js/r149/three.min.js`
- 通过 `document.write` 链式降级，确保 file:// 双击打开仍能加载。
- 自测时通过 `puppeteer-core` 的 `setRequestInterception` 将 CDN URL 重定向到本地 `node_modules/three/build/three.min.js`，做离线可复现的冒烟。

### 2.2 渲染策略
- `outputEncoding = sRGBEncoding`（r149 兼容字段名）+ `ColorManagement.legacyMode = false`，保证颜色按设计显示。
- `MeshLambertMaterial({ vertexColors: true, flatShading: true })` —— 顶点色合并 + flatShading，呈现「low-poly 折面」风格。
- 按构件类型合并为 ~36 个 Mesh（栌斗 / 华栱 / 斗 / 横栱 / 令栱 / 耍头 / 枋 / 撩檐枋 / 长趴梁 / 短趴梁 / 太平梁 / 雷公柱 / 4 老角梁 / 4 由戗 / 4 仔角梁 / 76 檐椽 / 76 飞椽 / 望板 / 瓦垄 / 戗脊 / 走兽 / 瓦当 / 宝顶 …），绘制批次可控（演变长廊同屏 5 亭约 150 Mesh）。
- 自写极简轨道控制（左键旋转 / 滚轮缩放 / 右键或 Shift+左键平移 / 双指缩放 / 空格复位）—— 减少外部依赖与 CORS 风险。

### 2.3 营造参数体系（单一数据源）
以斗口 K（= 材厚）为祖，所有尺寸按分°（= K/15）倍数派生：

```
caiG  = caiRatio · K                   // 材广（单材高）
qie   = 0.6 K                          // 栔高（6分°）
zuCai = (caiRatio + 0.6) K              // 足材（21分°）
tiaoLen = 3 K                          // 每跳出跳长（30分°/3斗口）
dgOut = tiao · 3K + 0.6K               // 斗栱自柱中出挑
dgH   = (2.0 + tiao·(caiRatio+1.4) + caiRatio + 2.4) · K   // 斗栱竖向通高
beamH = 2.2 · caiG                     // 趴梁／太平梁高
raftD = 1.2 K                          // 椽径
yEave = yDgTop + raftD - profileH(tp) // 檐口标高
apex  = yEave + juTotal                // 屋面攒尖顶
```

每朝斗口 K 由面阔 4 m 反推，并使 `柱高 / 斗口` 落在史实范围（清 ≈ 60 斗口，明 ≈ 46 斗口，宋/元 31–36 斗口，唐 ≈ 28 斗口），形成单调的「由疏朗到繁密」序列。

### 2.4 层级装配架构
九层自下而上（自台基至宝顶），竖向 Y 严格串联：

| 层 | 关键 Y 公式 | 承上 |
|---|---|---|
| 0 台基 | yPlat = platH | — |
| 1 柱础 | yPlinth = yPlat + plinthH | 台明顶 |
| 2 檐柱 | yColTop = yPlinth + colH | 柱础顶 |
| 3 额枋·平板枋 | yDgBase = yColTop + pph·K | 柱头 |
| 4 斗栱 | yDgTop = yDgBase + dgH | 栌斗 |
| 5 梁架 | yTaiping = yDgTop + 2·beamH | 撩檐枋（长趴梁＋短趴梁十字搭接＋太平梁） |
| 6 角梁·由戗 | 跟由 檐檩 → 雷公柱顶 | 撩檐枋转角 |
| 7 椽望 | 椽底 = yDgTop；望板即屋面 | 撩檐枋 |
| 8 瓦作·戗脊 | 同望板 | 望板 |
| 9 宝顶 | 底 = apex = yEave + juTotal | 雷公柱顶 |

为消除「构件穿模」，柱身做端面倾斜补偿（侧脚使端面微倾，按 sinθ 上下各让出半径，柱底恰落柱础顶、柱头恰抵普拍枋底）；飞椽、瓦垄、戗脊、宝顶均贴合屋面参数化曲面。

### 2.5 翼角「生出·起翘」的数学表达
檐口平面轮廓：以 `aEave / max(|cosφ|,|sinφ|)` 为正方形基线半径；角部按 `w = (min/max)^qPow` 加权 `sheng`（沿对角线生出），并对起翘 `lift` 用 `g(t) = ((tp-t)/tp)^qLift` 做从檐口到檐檩的衰减 —— 因此 `r(t) = rBase·(1-t) + sheng·w·g(t)`，保证 **檐檩为水平方环**（无角部变形），而 **起翘全部由檐檩以下的檐椽/飞椽/仔角梁完成**。这与中国大木作「檐檩老角梁上平、檐椽飞出翘」的力学本质严格一致。

### 2.6 朝代形制演变
五个朝代按单一参数表驱动，每朝构件尺寸皆由该朝 K 派生（参见 `result.json#dynasties`）。关键形制指标严格单调：

| 指标 | 唐 | 宋 | 元 | 明 | 清 | 趋势 |
|---|---|---|---|---|---|---|
| 斗口 K (cm) | 10.90 | 9.95 | 8.87 | 7.00 | 5.42 | ↓ |
| 斗栱高／柱高 (%) | 42.0 | 37.6 | 32.6 | 25.1 | 19.0 | ↓ |
| 柱高／斗口 (斗口) | 28.0 | 31.2 | 35.5 | 45.7 | **60.0** | ↑ |
| 出檐／柱高 (%) | 51.1 | 44.5 | 38.4 | 31.6 | 27.7 | ↓ |
| 举高／半跨 | 0.42 | 0.50 | 0.58 | 0.66 | 0.74 | ↑ |
| 翼角起翘 (cm) | 2.0 | 6.0 | 10.0 | 16.0 | 26.0 | ↑ |
| 补间攒数 (攒) | 1 | 2 | 3 | 4 | 6 | ↑ |
| 侧脚 (cm) | 5.5 | 3.7 | 1.9 | 0.6 | 0.0 | ↓ |

清 柱高/斗口 = 59.96 ≈ 清制「柱高六十斗口」标准；唐代举折 0.42 接近佛光寺东大殿实测 0.42 量级。

### 2.7 拆解与可视
- 分层解构滑杆 0–100%：每层沿 +Y 方向以「承托关系链」位移：`pos.y = (chainLift[layer] · 0.55 + order · 0.16) · t`，其中 `chainLift[layer]` 是该层底面在拆解态下应处的 Y（即上一层顶面的 Y）。如此拆解时，**层层仍相承**，而不是脱离。
- 演变长廊：5 朝同屏，各亭配动态 HTML 标牌（朝代名 + 年代 + 关键指标），HTML 元素每帧随投影位置更新。
- 拾取：自写 Raycaster 悬停高亮（emissive 切换）+ tooltip；点击锁定信息面板（构件名 / 所属层 / 形制说明 / 材分尺寸 / 承托关系）。

## 4. 已知工程取舍

- **斗栱铺作采「单栱造 + 十字搭接错位」近似**：实际宋以后有重栱造（瓜栱+慢栱叠置），本实现以华栱 足材 + 横栱 单材错位描述，已能清楚呈现铺作层叠；为避免构件互相穿越，未建模榫卯咬入的微穿模。
- **角科由「两向正交华栱+一斜由昂」组合表达**，斜由昂为简化楔形，未在 1:1 标架上做斜翘细节。
- **瓦垄以「波纹面 + 顶点色垄/沟交替」实现**，未能为每垄单建独立 Mesh，瓦当亦为合并小柱体；视觉上呈现筒板瓦对比即可。
- **法式 / 清制若干数值与史实间取折中**：例如斗口 K 选择使面阔恰好对应常见四柱方亭（小亭通常面阔 1.5–4.0 m），而非完全套用大型建筑规范。指标单调性与各朝制度定性严格一致；绝对值以「可量测的形制标尺」方式呈现于信息面板供审阅。
