## 任务要点

- 以 WebGPU 为底层渲染管线，纯代码构建车体、炮塔、125 mm 主炮、六对负重轮、履带和细节件，不引用外部三维模型。
- 提供全车装配检视、改型与内构考证、专业渲染工作室等相互隔离的功能页。
- 表达 VT-4 标准版、VT-4 A1 和 VT-4 P 的外观与选配差异，并能高亮改动区域。
- 构建动力舱、战斗舱、驾驶舱、自动装弹机和三人乘员战位，支持 X-Ray、剖切或半透明检视。
- 支持实时预览与静止累积渲染、相机与曝光参数、多环境预设、程序化地面和粒子效果。
- 提供 4K / 8K 大画幅导出能力，并明确实际实现与硬件限制。

## 自动化验收建议

- **启动与兼容性**：在支持 WebGPU 的 Chrome / Edge 中通过本地 HTTP 服务启动；记录适配器初始化、控制台错误和首帧状态。
- **程序化资产约束**：检查工程中不存在 `.gltf`、`.glb`、`.obj`、`.fbx` 等外部模型依赖，网络请求不应拉取外部三维资产。
- **整车结构**：核对主炮、炮塔、车体、六对负重轮、主动轮、诱导轮、托带轮和履带是否可辨，旋转和缩放后仍保持装配关系。
- **改型差异**：逐一切换 VT-4、VT-4 A1、VT-4 P，确认几何确实变化，高亮区域与差异说明一致，不是只替换标签。
- **内构与解构**：测试 X-Ray、剖切、爆炸视图和舱室聚焦；检查动力舱、自动装弹机、驾驶台与乘员战位可见且可恢复。
- **渲染状态**：交互时累积应重置，静止后样本数应继续收敛；曝光、色调映射、景深和环境切换应产生可观察变化。
- **导出**：分别验证至少一次 4K 与 8K 操作路径，检查失败时是否给出可诊断信息；不得仅凭按钮存在判定导出成功。
- **稳定性**：快速切换标签、改型和相机模式，确认无持续报错、资源重复初始化或明显状态串扰。
