# Escape From Duckov（复刻版）· 浏览器端技术验证

用 WebGL2 在浏览器里复刻《逃离鸭科夫》的核心体验：**搜刮 → 战斗 → 撤离** 的完整闭环，
叠加《僵尸毁灭工程》式的**复杂角色状态管理**。

不需要构建产物 —— `dist/index.html` 是单文件产物，`game.js` 是整包 IIFE。

```
启动：  npm i && npm run build && npm start   →  http://localhost:8080/dist/
```

| 命令 | 作用 |
| --- | --- |
| `npm run build` | esbuild 打包 + 复制 index.html → `dist/` |
| `npm run watch` | 监听模式重打包 |
| `npm start` | 静态服务器（无依赖，Node 内置） |
| `npm test` | 纯数值层单元测试（node:test，20 项） |
| `npm run smoke` | Playwright 无头冒烟（77 项，含画面像素统计） |
| `npm run maps` | 五张地图逐一加载的回归（26 项） |
| `npm run check` | 只做架构检查（依赖方向 + 文件规模） |
| `npm run verify` | 上面全部串起来跑一遍 |

## 1. 我做了什么 / 没做什么

**做完的（可用、可验证）**

- 渲染：正交俯视 + 卡通描边 + 昼夜循环 + 7 段全屏后期（ACES 调色 / 暗角 / 热成像 / 雨幕 / 描边），
  三台同姿态相机按层分离（世界层 → 调色 → 角色层 → 热源层），角色因此天然保持高饱和固有色。
- 战术视野：DDA 射线生成可见多边形 → 头顶阴影蒙版 + **盲区实体直接剔除**（防作弊式，不是变暗而已）。
- 战斗：甲弹关系、部位命中、后坐力→散布、枪声引尸潮、曳光弹颜色按弹药等级区分。
- 敌人：A* 寻路 + 视线拉直、状态机（游荡/查看/追击/近战/远程/搜寻）、阵营内讧、Boss 特殊机制。
- 角色状态：9 部位伤病、**细菌感染（可治）与克诺克斯病毒（无解）双路径**、Moodle 系统、
  需求与体重、医疗处置（包扎/消毒/缝合/夹板/抗生素/手术）。
- 物品：网格制背包 + 装备栏 + 保险箱、容器搜刮、九阶段属性合成管道、武器改装（含全息预览）。
- 战局：天气状态机、撤离读条、超时尸潮、直升机事件、停水停电、版本化存档、藏身处与 NPC 任务。

**没做 / 明确放弃的**

- **无美术资源**：全部贴图与模型都是程序化生成（`gfx/textures/proc.js` 的 Canvas 噪声、
  `gfx/geo/duck.js` 的鸭子体块）。所以画面是"示意级"，不是"成品级"。
- **无音频**：`core/audio.js` 的接口留了，但没有实际音频实现。
- **只落地了一张地图**（零号区，72×72）。另外四张的**配置**已在 `data/maps.js`
  （地形密度、建筑类型、战利品表、敌人配比、撤离点都已定义），但地形生成器只针对零号区调过参数。
- 没有背包内的拖拽摆放（用点击代替），没有多人、没有反作弊。

## 2. 目录结构

```
src/
  main.js              主循环与装配（只负责编排，不含业务逻辑）
  game/
    boot.js            装配流水线：世界 → 渲染 → 系统 → 编译
    actions.js         事件 → 后果（跨系统接线的唯一位置）
  core/                RNG(可复现) / 事件总线 / 定步长循环 / 输入 / 版本化存档
  data/                纯数据：数值、地图、物品、武器、弹药、敌人、战利品、医疗
  gfx/
    materials/         toon 材质工厂 + 所有自定义 GLSL（描边/雨/热成像/全息/调色/暗角/光锥）
    textures/proc.js   Canvas 程序化贴图（草/水泥/沥青/木/金属/砖/瓦/布/土）
    geo/               程序化几何（鸭子本体+装备、单位盒）
  render/              相机装置、渲染器(EffectComposer)、场景视图、实例化池、
                       迷雾、敌人视图、粒子、曳光、手电光锥、热源
  systems/
    pure/              纯函数数值层（可脱离 three 单测）：弹道、属性管道、伤病、Moodle
    world.js           地图生成（种子可复现）
    vision.js          可见多边形 / 视线 / 盲区剔除
    pathfind.js        网格 A* + 视线拉直
    movement.js        移动与碰撞
    combat.js          开火编排
    health.js          伤病总控
    inventory.js       网格背包与装备
    weather.js         天气状态机与体温
    director.js        撤离 / 尸潮 / 世界事件
    hideout.js         设施升级与 NPC 任务
  ui/                  HUD、面板（背包/改装/搜刮/身体）、全屏界面、全息预览
  debug/hooks.js       window.__GAME / __DUCKBOID 调试接口
```

依赖方向由 `scripts/check-deps.mjs` 强制：
`data → systems/pure → systems → render → ui → game → main`。
任何反向依赖（比如 render 去 import ui）都会让 `npm test` 失败。

`grabAscii()` 值得一提：无头环境下我看不到截图，于是把后台缓冲打印成 ASCII 亮度图。
**画面里的每一个"看不见"的 bug 都是靠它定位的**（见下）。

## 3. 关键实现取舍

### 3.1 视线迷雾为什么用"头顶平面"而不是全屏后期

正交俯视下，世界空间 ≈ 屏幕空间。所以一张 `y=7.2` 的蒙版平面就等价于全屏后期，
而且**天然随相机缩放**，不需要在着色器里重建世界坐标。

代价是精度：整张地图压在 256² 的画布上（0.28 单位/像素）。用三层递减缩放做柔化半影 +
视距边缘的径向淡出把量化误差藏掉了。

上传是真金白银的开销，所以加了**双闸门**：

- 频率闸门：15Hz
- 指纹闸门：把可见多边形量化到 0.25 单位算哈希，**站着不动时零上传**

### 3.2 手电光锥不穿墙，但不读深度纹理

EffectComposer 的乒乓缓冲让场景深度图拿不到，为它单独开一路深度 prepass 不划算。
做法是 CPU 沿锥体撒 32 条射线，把命中距离写进一张 `32×1` 的 `DataTexture`，
着色器按方位角采样做边缘淡出。**"光束被墙切断"是几何精确的**，不是近似。

### 3.3 角色层为什么要单独一个 RenderPass

角色（鸭子）要保持高饱和固有色，不能被调色/暗角污染。
所以链路是：`世界层 → 调色 → 暗角 → 角色层 → 热源层 → 雨幕 → OutputPass`。
代价是角色不吃雾 —— 这是刻意的，也是所有 2.5D 俯视游戏的通行做法。

### 3.4 属性合成必须是唯一的九阶段管道

`systems/pure/statPipeline.js` 里那张阶段表是唯一真源：
`基础值 → 配件加值 → 配件乘值 → 弹药 → 技能 → Moodle → 环境 → 特质 → 钳制`。

顺序本身就是设计契约。**换顺序会改变结果**，所以其它地方禁止自己算属性。
UI 上的改装面板直接读这条管道，因此"面板上看到的数字"和"实际生效的数字"不可能不一致。

### 3.5 确定性

`Rng` 是 xorshift128，地图按种子生成。给定种子 → 地形、容器、敌人分布完全一致。
`__GAME.step(60)` 可以脱离 rAF 推帧，所以逻辑回归可以精确到帧。

## 4. 踩过的坑（都是实测出来的，不是猜的）

| 症状 | 根因 | 出处 |
| --- | --- | --- |
| 整个画面只有背景色，世界消失了 | `scene.background` 是 Color → three 因 `forceClear` 在**每个** RenderPass 都清屏，角色层把世界层抹掉了 | `main.js` 注释 |
| 正午和午夜一样黑 | 卡通渐变贴图 `Uint8Array` **溢出回绕**：`263 & 255 = 8`，最亮的一档反而近乎全黑 | `gfx/materials/toon.js` |
| 迷雾孔出现在地图另一侧 | three 默认 `flipY`，画布 V 轴与平面 UV 是反的 | `render/fow.js` 的推导注释 |
| 开了后期就全黑 | 调色在**线性空间**以 0.5 为支点做对比 —— 线性 0.5 是极亮值，整幅画面被压进暗部 | `gfx/materials/shaders/grade.js` |
| 屏幕上下有明显亮度梯度 | 正交相机视空间深度恒在 50~62，而雾的范围是默认的 34~78 | `main.js` 的 Fog 注释 |
| 弹级远高于护甲时伤害是 2 倍 | 原式分母 `armor-pen+2` 会变成负数，需要钳到 2 而不是 1 | `systems/pure/ballistics.js` |
| 装备手枪静默失败 | 物品查表只查 `ITEMS`，而武器在 `WEAPONS` 里 | `data/items.js` 的 `itemDef` |
| 改装与余弹在装备后丢失 | 武器实例按 uid 存在背包网格里，而装备后的物品已不在网格中 | 实例挂在物品对象上 |
| 停电永远不触发 | 分支条件写成 `if (!powerOn && day >= powerDay)`，永远为假 | `systems/director.js` |
| 头部/躯干血量归零却死不了 | 自然愈合在同一帧把 0 抬回正数；致命判定必须**先于**恢复 | `systems/pure/injury.js` |
| 农场镇 / 风暴区一进去就崩 | 地图配置写的是 `farm_mine` / `four_knights`，而敌人表里的 id 是驼峰命名 | `data/maps.js` + 生成侧防御 |
| 风暴区天气会飘走 | 风暴区必须锁定雷暴，不能跟着马尔可夫链迁移 | `systems/weather.js` |

## 6. 验证

三层测试，共 123 项断言：

**`npm test`（20 项，node:test，纯逻辑）** —— 甲弹公式的四组边界值、九阶段属性管道的顺序语义、
弹药等级、克诺克斯病程 48~96 小时、抓伤/撕裂感染率抽样、脏绷带 3 天必感染、
抗生素可治细菌但治不了病毒、不缝合的深度伤口不愈合、恐慌的累积/恢复/特质修正。
这一层不加载 three、不启动浏览器，所以跑得飞快，改数值时应该第一个跑它。

**`npm run smoke`（77 项，Playwright + swiftshader）** —— 覆盖：

- **渲染**：WebGL 无错误码（着色器真的编译通过了）、画面非全黑/非过曝/有明暗层次/有色彩多样性。
  最后三项是像素统计 —— 无头环境下无法肉眼看图，只能量化。
- **迷雾**：静止零重绘、移动会重绘、视野锥随朝向变化、视距收缩后几乎无可见实体。
- **战斗**：开火扣血、产生曳光、枪声引尸群、手电光锥被墙截断、200 敌人仍受 draw call 预算约束。
- **数值**：甲弹公式四组边界值、克诺克斯病程落在 48~96 游戏小时、抓伤/撕裂感染率抽样、
  脏绷带 3 天后必感染、骨折惩罚与夹板恢复、恐慌放大瞄准惩罚。
- **系统**：A* 寻路、天气改变视距、撤离读条、超时尸潮、停水停电、直升机、存档版本与容错。

**`npm run maps`（26 项）** —— 五张图逐一加载，验证配置里的敌人/Boss id 全部可解析、
地形能生成、撤离点与容器存在。这张网是专门用来抓"数据里打错一个 id 就整张图起不来"的。

性能护栏用**软件光栅基线**而不是"60fps"：CI 里跑的是 swiftshader（纯 CPU），
实测该环境是填充率受限（130k 像素 25fps / 518k 8fps / 922k 6fps，严格反比于像素数）。
真实 GPU 上远不是这个量级。所以帧率断言只用于捕捉"引入了新的每帧算法成本"这类回归。
