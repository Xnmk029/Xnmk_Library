# FPV 穿越机花飞模拟器 — 技术说明（单文件实现）

**产物**：`index.html`（唯一交付物，双击即用，零外部依赖 —— 无 CDN、无第三方库、无构建步骤）
**运行环境**：任意现代浏览器（Chrome / Edge / Firefox，需支持 WebGL）。渲染层为手写 WebGL（WebGL2 优先、WebGL1 兼容回退），物理层 100% 手写，未引用任何物理引擎。

---

## 一、物理架构

整体是「固定步长刚体动力学 + PID 内环速率控制」的经典 Acro 架构：

```
摇杆输入 ──expo曲线──► 目标角速度 ω* ──► 三轴PID ──► 控制力矩 τ ─┐
                                                                ├─► 转动方程 I·ω̇ = τ − κω − ω×(Iω)
油门 ──推力曲线 T = Fmax·t^γ──► 体轴推力 R·(0,T,0) ──────────────┼─► 平动方程 m·v̇ = ΣF − Cd·|v|·v
重力 (0,-mg,0) ────────────────────────────────────────────────┘
姿态: R ← R·Exp(ω dt)   （每步 Gram-Schmidt 重正交化防漂移）
积分: 500 Hz 固定步长 + 帧间累加器（与渲染帧率解耦，保证数值稳定）
```

- **平动力学**：`m·a = R·(0,T,0)ᵀ + (0,−mg,0)ᵀ − Cd·‖v‖·v`。推力沿**体轴 +Y**（机体上方向量经 SO(3) 旋入世界系），气动阻力严格为**速度二次律** `F_d = −Cd·‖v‖·v`。
- **转动动力学**：对角惯量张量 I≈(1.2,1.2,2.2)×10⁻³ kg·m²，包含陀螺耦合力矩 `−ω×(Iω)` 与机械角阻尼项；角加速度 `α_i = (τ_i − [ω×(Iω)]_i)/I_i`。
- **电机/电池模型**：推力随油门按可调指数曲线（默认 γ=1.35）输出；电池电量随机头时间消耗，电压跌落使最大推力衰减至 70%（满电基准的线性映射）。
- **PID 闭环**：每轴独立 Kp/Ki/Kd，误差为目标角速度与陀螺实测值之差；含积分限幅抗饱和、力矩上限执行器模型。默认参数按 5 寸花飞机（650 g / 推重比 ≈ 2.5）手工整定，响应时间常数约 25–30 ms。
- **碰撞**：地面平面 + 场地障碍的解析 SDF（圆环 torus / OBB / 直立圆柱三类），球体近似机身（r=0.12 m）做穿透修正与恢复系数 0.42 的冲量反弹；大冲击或翻覆判定坠机并锁定，需复位。
- **失控保护（Failsafe）**：RSSI 随 Home 距离线性衰减（前 15% 满格），<7% 触发 FAILSAFE 切断电机（机体自由坠落），回到 >28% 自动解除——模拟真实图传链路的迟滞恢复行为。

## 二、SO(3) 积分方案（核心约束）

- **全程不出现欧拉角积分**：姿态唯一状态是旋转矩阵 `R ∈ SO(3)`（体→世界，3×3 列主序存储），不存在万向节死锁。
- **指数映射精确积分**：每个子步将角速度乘步长构成旋转矢量 `φ = ω·dt ∈ so(3)`，用 Rodrigues 公式计算矩阵指数：
  `Exp(φ̂) = I + (sinθ/θ)·φ̂ + ((1−cosθ)/θ²)·φ̂²`，其中 `φ̂² = φφᵀ − θ²I`；
  `|φ| < 10⁻⁴` 时切换泰勒级数 `k₁=1−θ²/6, k₂=½−θ²/24` 保证数值稳定。体坐标系角速度对应**右乘**：`R_{k+1} = R_k · Exp(ω dt)`。
- **漂移抑制**：每子步执行一次保留手性的 Gram-Schmidt 列重正交化（O(30) flops），长时间滚转/翻滚不会累积尺度误差。
- **相机与推力方向**均直接取自 R 的列向量（right/up/back 基），FPV 相机倾角通过绕体轴 X 的解析基旋转实现，同样不经过欧拉角。

## 三、VTX 后处理效果

渲染管线：场景先绘制到 **低分辨率离屏 FBO**（默认 0.7×，可调，本身即模拟图传的柔化感），再经全屏三角形的自定义 GLSL 后处理着色器输出到屏幕。信号强度由无人机与起点的距离决定，干扰度 `interference = pow(1−RSSI, 1.35)` 驱动以下效果渐进叠加：

1. **镜头桶形畸变**：宽角 FPV 镜头的径向畸变逆映射（出界处压黑边）。
2. **雪花噪点 Static Noise**：2px 块状白噪（hash 噪声，时变种子）按强度混入画面，弱信号时趋于满屏雪暴。
3. **横向画面撕裂 Horizontal Tearing**：以 3px 行为单位做伪随机行位移，撕裂概率与位移幅度随干扰度增长，伴随整帧水平抖动与偶发行丢失（dropout 亮/暗条）。
4. **不同步滚动条纹 Rolling Bands**：两条不同速度/宽度的滚动亮度带（高斯剖面），带内叠加高频 y 向抖动，还原模拟视频的同步失锁滚纹。
5. **色差与扫描线**：RGB 三通道径向分离采样 + 水平扫描线调制 + 暗角 + 对比度/黑位微调，构成"模拟味"底色。
6. **失联门限**：信号低于阈值时平滑过渡到"近黑屏 + 稀疏闪烁噪点"，同时 DOM 层弹出 NO SIGNAL / FAILSAFE 提示。

三项效果增益（噪点/撕裂/滚纹）+ 总强度均为设置页实时滑杆，以独立 uniform 注入着色器。

## 四、输入管线设计

采用**双源融合**的通道抽象，输出统一的语义化四通道 `{pitch, roll, yaw, throttle}`：

- **硬件遥控器/手柄（Gamepad API）**：每帧轮询 `navigator.getGamepads()`，默认 Mode 2 映射（左杆=油门/偏航，右杆=俯仰/横滚）；任一轴活动即自动接管（2 s 活跃窗口）。原始轴值经过 **死区收缩 → 归一化重缩放 → 反向开关** 三级处理；四个通道的**轴向绑定（axes[0..7] 或断开）与反向均可视化配置**，另有实时通道监视条辅助校准。
- **键盘虚拟摇杆**：方向键/WASD 以一阶惯性平滑逼近 ±1（模拟摇杆打杆手感），油门为保持式斜坡（W 升 / S 降，松开保持），贴近真实不回中油门。
- **融合策略**：按通道取两源中绝对值更大者（油门取 max），互不干扰。
- **语义映射到物理**：`ω*_x = pitch·rate`（抬头为正）、`ω*_y = −yaw·rate`、`ω*_z = −roll·rate`（右手系推导），再经 per-axis Expo 曲线软化中位区后送入 PID。
- **按键**：A/F 上锁解锁（清 PID 积分）、X/R 复位、B/C 循环视角、Y/Tab 设置菜单；全部按键边缘检测触发，避免连发。

## 五、其他

- **场地**：程序化地面（2 m 棋盘格 + 1 m 细网格 + 10 m 橙色主线 + 起飞引导带）、解析天空穹（梯度+太阳辉光）、三座异形圆环门、两组废墟墙体、八根条纹立柱，全部高对比配色并提供精确碰撞体。
- **视角**：FPV 第一人称（跟随 SO(3) 全姿态+可调上倾角）/ 追随机 / 第三人称目视，C 键循环。
- **参数持久化**：所有设置自动保存至 localStorage（失败安全降级），可一键恢复默认。
- **已知边界**：碰撞为球体近似（非网格级）；音频未纳入范围；Gamepad API 无法区分"硬件遥控器"品牌，但市面所有模拟器专用 USB 加密狗（如 FRSky/Crossfire sim 模式）均以标准手柄设备枚举，直接兼容。
