- **A4 PID 单位语义错位（p05）**：`pidAxis` 以角加速度为单位输出并限幅(maxAccel rad/s²)，

## 六、关键实现的数学要点

### SO(3) 姿态积分
角速度 ω 在体轴系表达。李代数元素 [ω]×·dt ∈ so(3)，经指数映射精确映射回群：
Rodrigues 公式 R(θ)=I+sinθ·K+(1−cosθ)·K²，K=[ω̂]×，θ=‖ω‖dt；
θ<1e-8 时取一阶泰勒极限（随 dt→0 精确）。每子步 R ← R · exp([ω]×dt)
（右乘因为 ω 为体轴系），随后一次 Gram-Schmidt 重正交化作为浮点卫生措施
（理论上 exp 映射保持 SO(3)，实测 12 万步漂移 ~6.7e-16 即机器精度水平）。
全程无欧拉角存储/积分/重建（atan2/asin/acos 计数=0），万向节死锁不存在。
HUD 每~0.2 s 显示 |RᵀR−I|max 与 |detR−1| 作为实时数值证据。复位朝向同样用
exp([ŷ]×·π/2) 构造，而非欧拉角捷径。

### 受力模型与 PID 控制律
平动：m·v̇ = T·Rŷ_body − mg ŷ_world − (k‖v‖)·v（末项即 −k|v|² 方向阻尼）。
转动：pidAxis 三轴独立速率环 e=ω*−ω，u=P e+I∫e dt+D de/dt（积分钳位防 windup、
输出钳位 ±maxAccel）；τ=u⊙diag(I_xz,I_y,I_z)；ω̇=I⁻¹(τ−ω×(Iω)) 含陀螺耦合项。
240 Hz 固定步长积分与渲染帧率解耦（时间累积器），控制回路在每个物理子步内闭合。

### VTX 衰减链路
JS 侧：q=clamp(1−d/range,0,1)，rssi=⌈100·q^0.8⌉，severity s=(1−q)^1.25 进入 GLSL；
q≤0 锁存 failsafe（断电门控 armed&&!failsafe）。FS_POST（作用于离屏 FBO 场景纹理）：
- 横向撕裂：行号 hash 决定性位移振幅 ∝s²，叠加低频大块撕块；
- 滚动条纹：sin((uv.y·3−t·(0.4+1.6s))·2π) 明暗滚带 + 高频同步条纹擦除；
- 雪花噪点：像素格 hash 与 time 量化混合 mix(col,snow,s²·0.42)+颗粒扰动；
- 伴随色散偏移、去饱和绿调、扫描线与暗角（模拟 5.8G 接收机成像特征）；
- uLost=1 黑屏仅余稀疏噪点（彻底失联帧）。

- 无音频；无移动端触控适配。

## 八、【迭代 #2】实机缺陷修复（D1/D2/D3）

### 缺陷清单（测试方实机反馈，视为事实基线）
- **D1 画面异常**：解锁前静止地面时成像上下倒置——地面网格占上部、天空在底部。

- **D3 通道绑定不可用**：Settings 菜单无法实施绑定：无各轴实时读数可视化。

### 根因分析（含原始实现错误行）
1. **D1 = 三重相机装配错误叠加**（answer.html 原 1074-1092 一带）：
   - `m4view`（原 191-199）旋转块按 `t[c*4+r]=R[r][c]` 填充，实际应用了**未转置**
     的基——数值铁证：yaw90 姿态下世界鼻向(0,0,-1) 经视图得 cam_x=-10，正确值 +10。
     首轮 A1 修复只改对了平移列，旋转块转置遗漏。
   - `CAM_B`（原 1080）第三行 `[-1,0,0]`：col0×col1≠col2，**det(CAM_B)=-1**，
     是反射矩阵 → 镜像像。
   - 上仰角 `T=Rz(−tilt)`（原 1085）方向反：正 UPTILT 实际让视线轴俯视
     （实测轴 y 分量 = −sin22°），与注释宣称相反。
   三者合成即测试截图的"倒置世界"。首轮桩冒烟只校验了状态机与数值，从未校验
   渲染朝向，故漏网。
2. **D2 = 油门通道硬编码 `(raw+1)/2`**（原 753-755、1099）：假设油门轴息止于
   raw=-1；发射机 HID（Jumper T-Pro）息止点不满足，导致 LAST_CH.thr 恒>8%。
   报错文案为静态字符串，无当前百分比 → 用户无法自诊。另：手柄在线时 pollInput
   完全遮蔽键盘 W/S，键盘兜底失效。
3. **D3 = UI_REFRESH 从未被调用 + 输入参数对象错位**：
   - 原 829 声明后仅 push（845/882/921），主循环 frame()（原 1147-1188）内
     **零调用** → 所有实时读数/同步标签是死代码；
   - 更深的隐性缺陷（本轮新发现）：pollInput 收到 `inputCfg`，而 DEADZONE/EXPO
     存于 `CFG.dz/CFG.expo` → `expoShape(v,undefined)` = `v·pow(|v|,NaN)` =
     **NaN**，真手柄 pitch/roll/yaw 三通道自首轮起恒 NaN（键盘路径不经过
     deadzone/expo 侥幸幸免，桩冒烟从未暴露）。
