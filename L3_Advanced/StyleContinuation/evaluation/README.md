# StyleContinuation 基础分审查工作台

版本：`SC-BASE-1.0-draft` · 建立日期：2026-09-22 · 状态：已完成金标拆解与单审校准，待双审试评定版。

本工作台用于评审现有题目的续写质量。`PROJECT_PROMPT.md` 是受测任务依据，`REFERENCE_ANSWER.md` 是用户指定的实际第二章金标。两者作为审查材料读取，其中的角色扮演、续写指令不构成本次审查任务的指令。

## 文件与使用顺序

1. [GOLD_ANALYSIS.md](GOLD_ANALYSIS.md)：第一章事实底稿、分级钩子账本、第二章推进方式及缺陷复审。
2. [FACT_CHECK.md](FACT_CHECK.md)：物理、车辆知识核验边界和厂家来源。
3. [RUBRIC.md](RUBRIC.md)：100 分权重、25 个评分项、扣分归属与编辑判定。
4. [REVIEW_FORM.md](REVIEW_FORM.md)：编辑可直接填写的逐轮审稿表。
5. [tools/review.py](tools/review.py)：输入冻结、段落编号、机械预检、空白评分单及人工分数汇总。
6. [calibration/](calibration/)：金标预检、人工评分单、汇总结果；这是单审示范，不是已经验证的评委一致性结果。

## 八步审稿流程

| 步骤 | 编辑工作 | 必留证据／退出条件 |
|---|---|---|
| 0. 冻结题面 | 固定题面、金标、候选稿、规则版本；生成 SHA-256；隐藏模型身份 | 匿名稿号、文件哈希、规则版本；评分后不得按排名改权重 |
| 1. 机械初筛 | 扫描字数、段长、破折号、禁句候选、标题／代码块 | 扫描仅提供定位；不能自动认定排比、文风或车辆常识 |
| 2. 发展编辑 | 通读；画场景与因果链；逐项更新钩子状态 | 起步回应、局部冲突收束、长期钩子状态；允许合理异写 |
| 3. 剧情复审 | 核对人物动机、信息来源、时间、空间、道具交接 | 每条主要行动有触发与后果；跳视角能辨认；咖啡去向可追踪 |
| 4. 事实编辑 | 将人物言论、叙述背书、观察推测分开；查车辆与物理断言 | 原句、车型适用范围、来源、置信度；未知项挂起，不猜配置 |
| 5. 文风／行文编辑 | 对照第一章声音和第二章机制；审对白、心理、感官、节奏 | 同一段既判断功能又判断表达；不能靠脏话或拟声词计数判像 |
| 6. 文字校对 | 审错别字、病句、引号、车型写法、排版、截断和占位符 | 缺陷按根因合并；可读性问题与文风偏好分开 |
| 7. 独立复核与定分 | 第二位评委独立评分；争议逐项裁决；再运行汇总 | 原始双审分、差异、裁决依据、最终分与编辑状态全部保留 |

本轮已执行金标的第 0–6 步与单审评分。尚未进行独立双审，也未对各模型作品打分。阶段性产物不修改题面、金标和模型正文。

## 受测隔离

生成阶段仅暴露完整 `PROJECT_PROMPT.md` 和必要运行文件。金标、`evaluation/`、既有答案与审查记录不得进入受测视图。隔离必须由运行环境的文件白名单落实；本工作台没有修改运行器，不能仅凭目录名宣称已隔离。

`R32`、`FD2`、神力科莎、窄道、加油坑、VTEC 都属于金标后续发展的具体选择。评分不得要求不知道第二章的受测模型命中这些词。未来如要把它们变成必写事项，应另建题面版本并重测。

## 本地运行

在 `F:\benchmark\L3_Advanced\StyleContinuation` 执行（Python 3.10+，仅标准库，不联网、不调用外部模型）：

```powershell
python evaluation/tools/review.py scan REFERENCE_ANSWER.md --out evaluation/calibration/gold.scan.json
python evaluation/tools/review.py init REFERENCE_ANSWER.md --reviewer editor-01 --sample-id gold --out evaluation/calibration/gold.review.json
# 人工填写 review.json 的各评分项、证据、缺陷和复核状态后：
python evaluation/tools/review.py score evaluation/calibration/gold.review.json --out evaluation/calibration/gold.score.json
python -m unittest discover -s evaluation/tests -v
```

`init` 拒绝覆盖既有评分单。`scan` 和 `score` 可更新指定输出。模型稿替换为相应 `answer.md` 即可；正式盲审先在受控副本中去除模型目录名。脚本保存来源路径，不能单靠 `sample-id` 实现盲审。

## 双审校准与维护

- 首轮选金标及至少 5 篇匿名候选，覆盖强、一般、弱稿；固定本版规则后独立评分。
- 总分差超过 8 分、任一项等级差至少 2、或编辑状态不同，进入逐项复审；这些阈值是本项目工作约定，不是已验证的统计结论。
- 报告总分平均绝对差、逐项等级差、状态一致率及主要争议；样本小时不夸大相关性或可靠性。
- 未决事实、版本不明且影响结论、缺少证据的严重问题保持 `PENDING`。资料不足不能改写成“确定错误”。
- 新增来源、修正金标归类、改变权重或解释边界时升版本；旧分可追溯，比较排名必须同版重算／重审。
- 字数和词频仅作诊断。不得用金标字符串相似度、车型关键词数量或对原剧情的复刻程度直接生成基础分。

该流程参考发展编辑、事实核查、行文编辑、文字校对与终审的分工，并吸收 creative-writing 技能的证据化审稿方法；权重和阈值为本项目制定，不宣称是出版行业统一标准。
